## 04 공유 재고 원본과 백업 경계 (2026-10-22)

공유 상품은 기존 원본 행을 여러 행사에서 참조한다. 부스 v2에는 공유 매핑/행사 일정/직접 변경 원장을 포함하고, 다른 보관 계정의 상품은 이름·기본 가격·수량·소유 매핑만 보존한다. 원장에 담긴 타 부스 배정 상세도 내보내기에서 다시 제거한다. 직접 부스가 없는 작가 보관 계정도 v2로 자기 원본/소유 관계/변경 원장을 보존한다. 다른 부스 거래까지 독립 복원하는 파일은 아니며 전체 교체 복원은 차단한다. [04 구현·복구 경계](artist-booth-transition/04-implementation.md)를 따른다.

## 작가 연결 출처와 백업 (2026-10-22)

03의 부스 백업 v2는 해당 부스에 참여하는 독립 개인 프로필/소유 관계와 연결 감사, 초대 발급/만료/철회/수락 메타데이터를 포함한다. 초대 원문과 token_hash는 제외하며 복원해 초대를 재활성화하지 않는다. 다른 부스의 연결 감사/거래는 포함하지 않는다. 개인 작가의 여러 부스 자료 전체 백업·복구는 별도 후속 범위다. 프로필 연결은 원본 재고/거래를 복사하거나 이동하지 않고 관리 관계만 추가한다. 잘못된 연결 정정은 [03 정정 절차](artist-booth-transition/03-implementation.md)를 따른다.

## 실제 기존 자료 백업·이관 (2026-10-22 후속)

서비스 운영 전인 현재 DB의 기존 admin 행사 자료는 사용자 요청으로 02 이관을 완료했다. [이관 기록](artist-booth-transition/02-data-migration.md)에 원본 보존과 백업 경로를 기록했다. 이관 전 원본은 관리 CLI의 `withbooth-legacy-migration` 형식으로 보관하며, 일반 마이페이지 v1/v2 복원 파일과 구분한다. 인증 비밀번호/해시·토큰·연결 주소를 포함하지 않는다. 앱의 공유 상태 전체 교체 복원 제한은 유지한다.

# 작가·부스 이관 계정의 백업 v2 (2026-10-22)

[02 호환 기반](artist-booth-transition/02-implementation.md)을 명시적으로 적용한 계정은 기존 `withbooth-account` 형식을 유지하되 version 2를 사용한다. 기존 원본 tables와 새 foundation 관계·초기 위치·이관 스냅샷·정산 귀속·취소/재고 감사 기록을 함께 서명한다. 인증 정보/토큰·실제 이미지 파일·기기 큐는 여전히 제외한다. 같은 3MiB 한도가 적용되어 이력 크기에 따라 백업이 거절될 수 있다.

공유 거래/재고를 과거 상태로 덮어쓰는 일반 복원은 제공하지 않는다. 이관 계정의 restoreAccount는 409이며 마이페이지도 복원 입력을 숨긴다. 구형 v1 파일을 공유 부스에 직접 적용하지 않는다. 원본 파일/서명을 유지한 별도 검증·변환과 자원 관계 확인이 필요하며, 범용 import/복원은 후속 작업이다. 다른 작가와 공유 자료가 있는 소유자의 탈퇴도 자산/소유권 정리 전 차단한다.

미이관 계정은 아래 기존 v1 계약을 유지한다. 이 문서 갱신으로 운영 자료를 이관하거나 백업·복원을 실행한 것은 아니다.

# 계정 전체 스냅샷 백업·복원 (2026-10-21)

마이페이지의 **계정 전체 백업·복원**을 사용한다. 행사별 백업·복원은 제거했다. 같은 계정의 모든 행사와 공통 상품/재고, 배정, 과거 판매 구성·가격·제작자, 판매 영수증, 입고/이동/로스 원장, 정산 비용·마감 스냅샷·마감 해제 이력, 분리 보관 원본을 같은 트랜잭션 스냅샷으로 보존한다.

복원은 현재 계정의 운영 자료를 백업 시점으로 **교체**한다. 기존 자료에 추가하거나 다른 계정으로 이전하는 기능이 아니다. 파일 선택 후 시점/행사/상품/판매 건수를 확인하고 현재 비밀번호와 교체 확인을 거친다. 복원 성공 후 다시 로그인한다. 같은 복원 요청 재전송은 이미 완료된 결과를 반환한다. 실패하면 삭제/삽입을 모두 롤백한다.

## 범위와 형식

- 형식: `withbooth-account`, version 1, 최대 3MiB JSON. 인증 비밀번호/이메일/토큰과 로컬 주문 큐를 백업하지 않는다. 소유권 확인용 계정 ID는 포함한다.
- 서버 HMAC으로 서명하므로 파일을 직접 수정하면 복원할 수 없다. 같은 서버 서명 키를 유지해야 한다. AUTH_SECRET(또는 현재 서버의 인증 서명 대체 키)을 교체하면 이전 백업의 서명이 유효하지 않으므로 키 교체 전 백업 정책을 별도로 마련해야 한다.
- 이미지 URL은 보존하지만 Blob/로컬 이미지 파일 자체는 포함하지 않는다. 원본 이미지 저장소가 유지되어야 한다.
- 모든 기기/탭의 판매를 중단하고 동기화해야 한다. 현재 기기의 미동기화 주문은 UI에서 차단하며 다른 기기 큐는 서버에서 확인할 수 없다. 복원 전 revision의 주문은 서버가 거절하므로 다른 기기는 온라인에서 새 데이터를 다시 받아야 한다.
- IndexedDB 주문 백업은 실패 진단용 별도 기능이며 계정 스냅샷 복원에 사용하지 않는다.
- `pos_account_restores`의 요청 영수증은 운영 스냅샷에 포함하지 않는다. 같은 요청 ID를 유지한 재시도에서 이후 거래를 다시 되감지 않도록 한다.

## 06 계약 정책과 이력 보존 (2026-10-22 후속)

이관 부스의 v2 백업은 `pos_booth_contract_policy`, `pos_booth_contract_commands`를 포함하며 현재 비밀번호는 저장하지 않는다. 신규 요청의 구형 지원 종료는 부스별 정책이고 원본 판매/정산/재고나 기기 큐를 삭제하지 않는다. 복구는 정책만 되돌려 종료 이후 거래를 유지한다. `admin_id`·이름 별칭·ID 매핑은 읽기/복원 참조가 남아 유지한다. v1/v2 읽기와 이관 계정 전체 교체 복원 제한도 유지한다. 상세·물리 삭제 전제는 [06 기록](artist-booth-transition/06-implementation.md)을 따른다. 이번에 실제 DB 종료/스키마 제거·기존 백업 변환은 수행하지 않았다.

## 06 실제 종료 자료 보존 (2026-10-22 추가 후속)

사용자 확인 후 admin 부스에 종료 정책을 적용했다. 실제 원본/관계/스키마 백업과 독립 DB 재현, 커밋 후 원본·다른 계정 무변경 대조를 완료했다. [실제 종료 기록](artist-booth-transition/06-data-retirement.md)의 Git 제외 백업 4개를 보존한다. 재현용 스키마 복사는 실제 DB의 모든 FK/트리거까지 복원한 실험이 아니며 원본 큐·이미지 파일도 포함하지 않는다. 과거 키·별칭과 기존 백업 읽기는 계속 유지한다.
