## 판매 저장·재전송 기반 개선 후 남은 위험 (2026-10-15)

큐/상태 분리 저장과 취소 시 실패 주문 삭제는 원자 트랜잭션/취소 명령 보존으로 개선했다. Web Locks 안에서 SYNCING 회수, 삽입 순서 전송, 실패 후 중단, 서버 receipt 보존을 추가했다. 신규 거래에는 구성 스냅샷을 사용한다. 아래 기존 분석 중 이 항목들은 이번 변경 전 상태를 설명한다.

아직 계정 소유 필드/마이그레이션·전체 행사 로그아웃 차단·지속 세션·오프라인 최초 준비·관리 큐·로컬 복원은 없다. 서버 기준 상태와 로컬 명령 재적용 병합도 없으며 큐가 남으면 로컬 상태를 보존하므로 원격 변경 표시가 지연된다. 리비전 충돌은 자동 폐기하지 않고 실패 큐를 유지하며 수동 해결이 필요하다. 첫 실패 뒤 후속 전송을 멈추므로 영구 오류 하나가 해당 행사 큐를 막을 수 있다. Web Locks 미지원 환경에서는 안전을 위해 업로드를 중단한다.

기존 스냅샷 없는 판매는 마스터 변경 이후 취소/정산 한계가 남는다. 이미 취소/삭제되어 배포 전에 사라진 판매 ID는 복구할 수 없으며 새 receipts 보호는 배포 후 기록한 ID부터 적용된다. receipts는 프로젝트 삭제 전까지 증가하므로 보존/정리 정책이 필요하다. 다중 기기 초과 판매·실제 PostgreSQL 동시성·실제 브라우저 종료/두 탭 경쟁 검증은 남아 있다. 운영 적용 전 별도 DB에서 CREATE 권한과 경쟁 시 재시도 동작을 확인한다.

# 위험 분석과 개선 순서

## 권장 작업 단위

2026-10-15 프로젝트 관리: 보관은 서버에서 판매·수정을 거절하고 클라이언트/캐시/같은 브라우저 탭에 읽기 전용 상태를 적용한다. 다른 기기의 오프라인 로컬 판매/대기 주문을 조회·잠글 수는 없다. 모든 기기에서 판매 중단·동기화 후 보관해야 하며 해제하면 기존 대기 주문이 재전송될 수 있다. 백업/복원은 서버 저장 자료와 이미지 URL만 포함하고 3MiB 한도다. 이미지 바이너리·미동기화 큐·과거 정리 원본은 제외한다. 실제 여러 연결 동시성/운영 마이그레이션·배포 검증은 남아 있다.

1. **데이터 유실 방지 — P0 완료:** 기본값 추가와 초기화 분리, 판매 보존, 미동기화 주문 차단 및 API 회귀 테스트 추가. 실DB·브라우저 검증은 배포 전 별도 수행.
2. **서버 거래 보장:** 판매·취소 트랜잭션, 재고 동시성, 멱등 키/취소 tombstone, 서버 입력 및 금액 검증.
3. **로컬 복구 보장:** 큐+상태 원자화, SYNCING 회수, 서버 응답 병합, 프로젝트 전환/다중 탭 검증.
4. **과거 기록 보장:** 주문 구성 스냅샷, 취소·제작자 정산 고정, 백업 복원 및 감사 이력.
5. **운영 기반:** 인증 강화, migration, 테스트/타입 검사/CI, 서비스 워커 업데이트 정책.

## 먼저 확정할 업무 규칙

- 인터넷 없이 여러 기기에서 같은 재고를 팔 때 허용할 초과 판매 및 충돌 해결 방식.
- 현금/계좌이체의 실제 수령 확인 시점과 취소·환불 상태를 별도로 관리할지 여부.
- 무료 상품, 세트 할인 배분·반올림, 제작자 정산 기준.
- 기본 상품 업데이트는 기존 항목을 덮어쓰지 않고 누락만 추가한다. 별도 메타데이터 갱신 정책과 판매 기록 보존 기간은 후속 확정이 필요하다.
- 신규 가입 공개 여부, 행사 직원의 공동 프로젝트 접근/권한 모델. 현재는 관리자별 프로젝트 소유만 구현되어 있다.

기존 12월 행사 정리는 지정된 admin 행사 ID 두 개에만 적용하고 pos_event_archives에 원본을 보관한다. 표식 삭제는 재정리를 유발하므로 보관 정책이 필요하다. dataRevision으로 옛 POST를 차단하며 로컬 미전송 주문은 ARCHIVED로 보존한다. 복원 UI 및 실제 브라우저 전환 검증은 남아 있다.

이메일 가입은 형식 검증과 DB 고유 제약을 적용하지만 소유 확인 메일은 발송하지 않는다. SNS 로그인 도입 전 provider 사용자 ID 기반 연결, 이메일 미제공 처리 및 인증된 기존 계정의 명시적 연결 절차가 필요하다. 이메일 일치만으로 계정을 연결하지 않는다.
