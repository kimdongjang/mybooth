# 위험 분석과 개선 순서

아래는 2026-10-14 코드 분석과 후속 P0 수정 결과다. P0는 데이터 유실을 우선 방지할 항목, P1은 재고/판매 정합성, P2는 운영·유지보수 항목이다. P1/P2는 코드 경로에 근거한 위험이며 실DB 장애 재현을 수행하지 않았다.

| 우선순위 | 코드 근거와 현재 문제 | 개선 목표 |
| --- | --- | --- |
| P0 완료 | upsertDefaults는 없는 기본 항목만 추가하고 기존 상품/세트/재고/판매 유지. resetDefaults는 상품·세트·재고 초기화, 판매 유지. 안내 문구 일치 및 미동기화 주문 차단 | API 회귀 테스트 3개/빌드 통과; 실DB·브라우저 통합 검증은 미실행 |
| P1 | finalizeSale/voidSale/replace*/seedProject에 트랜잭션 없음 | 실패 시 전체 rollback; 판매/재고/중복 처리를 같은 트랜잭션에 포함 |
| P1 | 판매가 재고 SELECT 후 별도 UPDATE; ID 존재 조회 후 별도 INSERT | 행 잠금 또는 조건부 차감과 원자적 idempotency. 동시 판매 시 음수 재고/중복 차감 방지 |
| P1 | voidSale는 판매 조회 후 복구·DELETE; 취소 후 원 판매 ID가 사라짐 | 취소 상태·이력 보존; 중복 취소/판매 재전송에도 한 번만 효과 적용 |
| P1 | 수량/가격/total/method/cart.type 검증 부족, total은 클라이언트 제공, 없는 세트도 재고 차감 없이 통과 가능 | 서버에서 상품·세트 존재/활성 여부, 양의 정수 수량, 0 이상 가격, 허용 결제수단 확인 및 금액 재계산 |
| P1 | 주문 큐와 posState가 별도 저장; 판매 스냅샷은 fire-and-forget | 로컬 주문·재고·판매 원자 저장 또는 큐 재생으로 상태 재구성 |
| P1 | SYNCING은 countWaiting에 포함되지만 getPendingOrders 재조회 대상에서 제외 | 종료/새로고침 시 남은 SYNCING 복구; 서버 멱등성 확보 후 안전 재전송 |
| P1 | sync 응답 상태를 버리며 loadState/mutate는 서버 전체 상태로 로컬 덮어쓰기 | 서버 상태와 미동기화 주문 병합; 대기 주문이 표시/재고에서 사라지지 않도록 검증 |
| P1 | SyncService lock은 한 JS 인스턴스 내에서만 적용 | 여러 탭/기기 중복 처리 방어; 서버가 최종 정합성 보장 |
| P1 | 동기화 배치 토큰/프로젝트 고정 및 전환 시 다음 주문 중단 구현; 이미 전송된 요청은 완료 가능 | 프로젝트 전환/로그아웃 시 진행 작업 경계 고정, 다른 관리자 토큰으로 재전송 방지 |
| P1 | 판매 lines에서 subItems를 제거; 서버 판매/취소와 제작자 집계가 현재 세트/상품 참조 | 판매 시점 구성·가격·제작자 스냅샷 저장, 그 스냅샷으로 취소·집계 |
| P1 | 설정 입력마다 replaceProducts 전체 삭제·재삽입; 상품 삭제는 상품/세트 변경을 별도 요청으로 병렬 시작 | 개별 변경 API 또는 버전 기반 충돌 검사; 상품/구성 변경 원자 처리 |
| P1 | loadProjects는 항상 서버 조회; 프로젝트 목록 로컬 캐시 없음 | 오프라인 재시작 정책 정의; 캐시한 프로젝트와 세션 복원 흐름 검증 |
| P1 | AUTH_SECRET 없으면 ADMIN_PASSWORD 또는 알려진 개발 기본값; 토큰 만료 없음 | 운영 시 secret 필수 검사, 토큰 만료/폐기 정책, 가입 정책·로그인 제한 정의 |
| P2 | 이전 단일 행사 스키마의 project_id/상품 컬럼/키는 자동 보완. 과거 NULL 행은 admin의 7월 서코행사에 연결; ID 충돌 시 전체 보존/실패 | 명시적 migration/version, 과거 행 소유권 확인 및 연결 절차; 운영 스키마 검증 |
| P2 | assertPostgresConnectionString은 DATABASE_URL 등도 허용하지만 설치된 sql pool의 기본 연결은 POSTGRES_URL | 연결 검사와 실제 드라이버 설정 일치; 실제 환경의 pooling 연결 확인 |
| P2 | legacy ADMIN_PASSWORD는 최초 INSERT ON CONFLICT DO NOTHING만 수행 | 환경변수 변경이 기존 비밀번호를 바꾸지 않음을 운영 절차에 기록 |
| P2 | 서비스 워커 캐시 버전 수동 관리, 설치 캐시 실패를 경고 후 진행 | 배포 버전과 자산 캐시 교체/오프라인 로드 검증 |
| P2 | FAILED 원인 저장 없이 고정 10초 재시도, SYNCED 누적, 복원 UI 없음 | 오류 분류/재시도 정책, 백업 복원/보존/정리 정책 마련 |
| P2 | 판매 CSV는 이름의 따옴표 escape가 없음; 집계 금액은 소수 발생 가능 | CSV 인용/스프레드시트 해석 정책, 원 단위 배분 규칙 검증 |
| P2 | 기본값 API 테스트만 추가됨; lint/typecheck 및 CI 없음; latest 의존성 혼재 | 판매·동기화 시나리오 자동화, 타입 검사·잠금파일 기반 CI |

## 권장 작업 단위

1. **데이터 유실 방지 — P0 완료:** 기본값 추가와 초기화 분리, 판매 보존, 미동기화 주문 차단 및 API 회귀 테스트 추가. 실DB·브라우저 검증은 배포 전 별도 수행.
2. **서버 거래 보장:** 판매·취소 트랜잭션, 재고 동시성, 멱등 키/취소 tombstone, 서버 입력 및 금액 검증.
3. **로컬 복구 보장:** 큐+상태 원자화, SYNCING 회수, 서버 응답 병합, 프로젝트 전환/다중 탭 검증.
4. **과거 기록 보장:** 주문 구성 스냅샷, 취소·제작자 정산 고정, 백업 복원 및 감사 이력.
5. **운영 기반:** 인증 강화, migration, 테스트/타입 검사/CI, 서비스 워커 업데이트 정책.

## 먼저 확정할 업무 규칙

- 인터넷 없이 여러 기기에서 같은 재고를 팔 때 허용할 초과 판매 및 충돌 해결 방식.
- 현금/계좌이체의 실제 수령 확인 시점과 취소·환불 상태를 별도로 관리할지 여부.
- 무료 상품, 세트 할인 배분·반올림, 제작자 정산 기준.
- 기본 상품 업데이트는 기존 항목을 덮어쓰지 않고 누락만 추가한다. 별도 메타데이터 갱신 정책과 판매 기록 보존 기간은 후속 확정이 필요하다.
- 신규 가입 공개 여부, 행사 직원의 공동 프로젝트 접근/권한 모델. 현재는 관리자별 프로젝트 소유만 구현되어 있다.

기존 12월 행사 정리는 지정된 admin 행사 ID 두 개에만 적용하고 pos_event_archives에 원본을 보관한다. 표식 삭제는 재정리를 유발하므로 보관 정책이 필요하다. dataRevision으로 옛 POST를 차단하며 로컬 미전송 주문은 ARCHIVED로 보존한다. 복원 UI 및 실제 브라우저 전환 검증은 남아 있다.
