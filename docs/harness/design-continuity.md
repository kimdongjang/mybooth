# 작가 중심 화면의 기존 디자인 적용 하네스

작성일: 2026-10-23. 이 문서는 디자인 정리 작업의 실행 지침이며 화면 수정 완료 기록이 아니다.

## 목표와 적용 범위

작가 중심 구조의 데이터·권한·메뉴 체계를 유지하면서 기존 WithBooth 화면의 디자인을 적용한다. 새로운 디자인을 제안하기보다 기존 화면의 페이지 골격·제목·필터·탭·버튼·표·카드·입력폼을 재사용한다. 클래스명만 붙여 비슷하게 보이게 하는 것으로 완료하지 않는다.

사용자가 명시적으로 다른 기준을 지정하지 않는 한, 기존 InventoryPage / DashboardPage / RevenuePage / ProjectsPage / AccountPage 및 PageLayout을 디자인 참고 대상으로 사용한다. 이 컴포넌트의 예전 API·권한·부스 전체 데이터 조회를 복사하지 않는다.

## 기준 버전과 로컬 변경 보호

- 구조 전환 PR #78 이전 디자인 비교 기준은 origin/main의 `84df618c00c24c267703662841fcc218a4ec7472`다. 작업 시작 때 이 커밋과 대상 파일을 기록한다. 이후 main이 이동해도 비교 기준을 임의 변경하지 않는다.
- 현재 로컬에는 사용자가 진행한 폰트·재고 화면·모바일 등 별도 수정이 있다. 디자인 작업은 해당 변경을 보존한 현재 작업 파일에서 진행한다. 과거 버전으로 파일 전체를 되돌리거나 기존 CSS 전체를 덮어쓰지 않는다.
- 우선순위는 사용자 최신 지시 → AGENTS.md 공통 규격 → 보존할 로컬 디자인 변경 → 지정한 과거 화면의 디자인이다. 충돌은 임의 혼합하지 말고 해당 화면의 작업 기록에 적는다.
- 기본 참고는 기존 코드다. 과거 버전의 화면을 직접 실행해야 하면 별도 작업 공간과 독립 DB를 사용한다. 기존 DB에 예전 앱을 연결하거나 검증을 위해 운영 DB를 변경하지 않는다.

## 반드시 지킬 시각 규칙

1. 페이지 제목과 우측 작업은 PageIntro를 우선 재사용한다. 헤딩 단계, 제목 위치, 본문 시작점을 기존 페이지와 맞춘다.
2. 버튼은 주요 저장·보조 작업·삭제/종료의 위계를 기존 화면과 맞춘다. 한 섹션 안에 모든 버튼을 주요 색상으로 강조하지 않는다.
3. 카드 외곽·헤더·본문·필드 그리드는 기존 DOM 구조와 CSS 선택자의 적용 범위를 함께 확인한다. account-form이나 management-fields를 붙이는 것만으로 다른 역할의 UI를 대체하지 않는다.
4. 같은 역할의 글꼴 크기·굵기·줄 높이는 모바일·데스크톱에서 동일하게 유지한다. /inventory 검색 조건의 공통 폰트 토큰과 최신 AGENTS.md 규칙을 따른다. 기존 CSS에 남은 반응형 폰트 예외도 수정 대상 영역에서는 제거한다.
5. 여백·테두리·색상·모서리·아이콘·컨트롤 높이는 기존 역할의 규격을 재사용한다. 임의의 페이지 전용 수치를 늘리거나 전역 CSS 마지막에 중복 덮어쓰기를 계속 추가하지 않는다.
6. 모바일 대응은 줄바꿈·열 수·폭·여백·가로 스크롤로 해결한다. 긴 작가명·상품명·부스명과 큰 금액을 고려한다.
7. 메뉴 이동에는 현재 위치를 표시한다. 실제 탭 패널 전환은 PageTabs를 검토하되 별도 경로 이동을 tab 역할로 바꾸지 않는다.
8. 요청하지 않은 설명·사용법·완료 문구·반복 성공 알림·빈 상태 요소를 추가하지 않는다. 필요한 오류·접근성 이름·기존 로딩 표시는 유지한다.
9. 비활성·읽기 전용·처리 중·오류 상태도 기존 스타일을 재사용한다. 오류 해결이나 읽기 전용 여부를 색상만으로 전달하지 않는다.

## 기능 보존 경계

디자인 수정에서는 API·DB·권한 판정·재고 계산·정산 계산·요청 ID·version·오프라인 큐·동기화 로직을 변경하지 않는다. 훅과 저장 핸들러를 보존한 상태에서 표시 컴포넌트·레이아웃·스타일을 정리한다. 기존 디자인 컴포넌트가 데이터 조회까지 포함하면 표시 부분만 추출해 새 데이터에 연결한다.

개인 화면에 부스 전체 조회를 다시 연결하지 않는다. 행사 참여 작가에게 운영자 메뉴를 노출하지 않는다. 행사 당일 작가의 행사 재고·판매가 변경 제한, 판매 담당자와 부관리자의 행사별 범위, 확정 정산 스냅샷과 미전송 주문 보호를 유지한다.

권한이나 계산 동작을 고쳐야 한다면 디자인 작업에 섞지 말고 별도 기능 변경으로 기록한다. 이 경우 해당 기능의 기존 테스트·빌드·하네스 검증 기준을 적용한다.

## 진행 순서

- [ ] 2. 개인 재고: 가장 자주 쓰는 목록 화면 하나를 먼저 맞추고 사용자 확인을 받는다. 여기서 정한 패턴을 이후 화면에 적용한다.
- [ ] 3. 재고 하위 화면: 상품 추가·상세·엑셀 등록·외부판매/로스를 맞춘다.
- [ ] 4. 개인 대시보드·수익현황: 기존 KPI·기간 필터·정산 목록 표현을 적용한다. 개인 조회 범위는 유지한다.
- [ ] 5. 행사 선택·부스 관리: 기존 행사 카드와 관리 폼 패턴으로 정리한다.

한 번에 모든 화면과 공통 CSS를 바꾸지 않는다. 각 단계는 참고 파일·대상 파일·표시 변경·기능 보존 범위를 먼저 정하고, 로컬 확인 의견을 다음 단계에 반영한다. 사용자의 수정 의견은 현재 화면뿐 아니라 같은 역할의 공통 규칙인지 판단해 기록한다.

## 작업 완료와 전달

디자인·레이아웃 전용 변경은 AGENTS.md에 따라 테스트·빌드·브라우저 자동화·스크린샷 검증을 기본 생략한다. 사용자가 검증을 명시적으로 요청하면 요청 범위만 수행한다. 사용자 로컬 확인 전에는 시각 검증 완료라고 쓰지 않는다. 문서 작성만으로 화면 수정까지 완료했다고 보고하지 않는다.

결과에는 변경한 화면과 기준, 디자인 외 동작 변경 유무, 검증 생략 또는 실제 수행 범위, 남은 사용자 확인 항목을 짧게 적는다. 별도 요청 없이 커밋·푸시·기존 PR 갱신·배포하지 않는다.
## 개인 재고 화면 수정 (2026-10-23)

사용자 지시에 따라 /inventory는 내 재고 전용이다. 부스 운영자의 대리 작가 선택은 개인 재고에서 제거하고 행사 판매 설정에 유지한다. 연결된 본인 작가 프로필의 재고를 합쳐 조회하며 수정 요청은 해당 상품의 ownerId를 유지한다. 신규 등록은 기존 기본 본인 프로필을 사용한다.

PersonalInventoryCatalog는 기존 InventoryPage의 브레드크럼·하위 메뉴·검색 필터·표·페이지 이동 스타일을 재사용한다. 목록에서 상품을 선택하면 개별 상세에서 상품 정보·이미지·재고 관리를 표시한다. 개인 목록에는 제작자 선택 조건을 두지 않는다. 서버 권한·재고 계산·정산·오프라인 큐는 변경하지 않았다.

관련 workspace-ui 자동 테스트 5개와 npm run build 통과. 기존 청크 크기 경고가 있다. 실제 브라우저 시각 비교·모바일·다기기·DB 쓰기 시나리오는 미실행이다. 로컬 수정이며 PR 갱신·배포하지 않았다.
## 행사 판매 설정 디자인 정리 (2026-10-23)

## 행사 상품 등록 연결 (2026-10-23 후속)

사용자 요청으로 /products의 관리 작가 선택과 접이식 등록 폼을 제거했다. 행사에 등록된 작가의 상품을 함께 표시하고, 목록의 새 상품 등록 버튼은 /products/new로 이동한다. 기준 커밋 84df618c00c24c267703662841fcc218a4ec7472의 ProductCreatePage와 현재 로컬 폰트·폼 변경을 보존한 등록 화면을 재사용한다.

등록 폼의 작가 선택은 현재 행사의 stockParticipants(참여 작가는 본인 행사 프로필)로 제한한다. 자유 입력 제작자 대신 ownerId를 전달하며 서버가 작가명을 결정한다. 기존 createArtistStock으로 최초 입고 전량을 현재 행사에 배정하고 등록 ID를 requestId로 재사용한다. 이미지는 등록 결과의 원본 재고에 연결한다. 목록·상세의 저장은 각 상품 ownerId를 유지하고 다른 행사 배정은 표시하지 않는다. 보관·마감·행사 당일 권한 제한과 기존 API·DB·주문 큐 계약은 유지한다.
