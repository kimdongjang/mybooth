# 개인 홈·재고·행사 화면 계약

2026-10-28 판매 중심 PR 코드 기준. 기존 제작자·행사 권한과 판매·정산 API의 범위를 유지한다.

## 개인 메뉴와 화면

- 선택 행사가 있으면 행사 목록·내 재고관리·대시보드 등 개인 화면에서도 헤더가 바뀌지 않는다. 헤더 한 줄의 `행사 메뉴`에 판매·판매현황·행사 판매 설정·행사 관리를 기존 권한 조건으로 두고 별도 2단 `header-secondary`는 쓰지 않는다. 같은 줄의 `내 계정`에 행사 목록·내 재고관리·대시보드·마이페이지를 둔다. 개인 화면에서는 행사 메뉴에 현재 표시를 두지 않고 `내 계정`과 해당 항목을 현재로 표시한다. 모든 메뉴 항목은 왼쪽에 역할별 아이콘을 둔다.
- 767px 이하에서는 로고·행사 이름·동기화 상태·햄버거 버튼을 한 줄에 두고 같은 메뉴 구성을 햄버거 패널(`메뉴`, `aria-expanded`, `aria-controls=header-navigation`)로 대체한다. Escape·바깥 클릭·페이지 이동 시 닫는다. 헤더 행사 이름은 배경 없는 선택기이며 데스크톱·모바일 모두 앞 아이콘을 표시하지 않는다.
- 선택 행사가 없으면 기존 상위 메뉴 판매·행사 목록·내 재고관리·더보기(대시보드·마이페이지)를 쓴다. 판매는 펼침 없이 접근한다. 수익현황은 헤더 메뉴에서 제외했고 마이페이지 하위 메뉴와 `/account/revenue`, 기존 `/revenue` 링크로 접근한다.
- 대시보드는 눈에 보이는 제목과 행사 목록 링크, 확인 필요 항목·내 재고·내 정산·내 판매액을 표시한다. 행사 선택 카드·예정/지난 행사 목록과 집중 행사 지정은 제거한다. 확인 항목이 없으면 숨기고 기간 필터는 본인 판매 스냅샷 금액에만 적용한다. 재고와 확정 정산 대기는 전체 기간이며 행사 전체 통계를 개인 판매액에 합산하지 않는다.
- 재고 하위 메뉴는 내 재고관리·재고 일괄등록·내 판매내역 순이다. `/inventory/sales`와 이전 `/inventory/movements`는 판매내역 화면을 표시하며 개인 로스 입력 화면은 제거했다. 기존 차감 원장과 행사 내부 로스 계약은 보존한다.
- 내 재고 목록의 검색·테이블은 제작자 프로필이나 조회 데이터가 없어도 빈 목록으로 표시한다. `/inventory/new`의 기존 등록 폼도 표시하되 프로필과 재고 조회가 준비되기 전에는 저장을 막는다. 프로필이 없으면 등록 불가 오류를 표시한다. `createArtistStock`의 소유자 범위·0원/0개 최초 등록 계약은 유지한다. 프로필 생성 컴포넌트 `ArtistAccount`의 생성 폼은 현재 마이페이지에 연결되어 있지 않으며 이번 목록 표시 수정에서 계정 기능을 변경하지 않는다.
- 내 판매내역은 `artists=history`의 본인 귀속 행사 상품·수량·금액·취소 상태만 표시한다. 검색·상세 조건·열 정렬을 제공한다. 온라인 판매 입력은 상품/판매일/수량/총금액/선택 메모 팝업 UI까지이며 저장 버튼은 비활성이다. 저장·재고 차감·취소·수익 반영 API는 후속이다.

## 행사 정보와 선택

- 행사 위치는 별도 `pos_event_details(project_id, venue)`에 보존한다. 기존 프로젝트 행을 변경하지 않아 이관 원본 지문을 유지한다. 계정/프로젝트 삭제와 참조 관계는 외래 키로 유지한다.
- 생성과 구성 가져오기 UI는 행사명·위치·시작일·종료일을 입력받는다. API는 기존 이름만 보내는 호출도 허용한다. 위치는 200자 이내 문자열, 날짜는 유효한 날짜이며 시작일≤종료일이어야 한다. 일정은 기존 `pos_event_stock_policy`를 재사용하므로 행사 기간 재고 수정 정책에도 반영된다.
- 생성과 장소/일정 저장은 같은 트랜잭션이다. 구성 가져오기는 장소·기간을 요청 지문에 포함하며 같은 ID/같은 내용은 기존 결과, 같은 ID/다른 내용은 409다. 행사 정보 수정의 기존 운영 권한·비밀번호 검증을 유지한다.
- 백업/복원과 구성 가져오기는 `project.venue`를 보존한다. 기존 백업의 위치 생략은 빈 값으로 취급한다. 행사 목록은 기존 권한 범위 안에서 위치·일정을 함께 반환한다.
- 행사 목록은 진행 중·예정·일정 미설정·종료/정산 마감/보관 섹션 순이다. 기존 한국 날짜·마감·보관 판정과 정렬을 유지한다. 행사명·부스·일정·장소·상태와 권한별 주요 이동 버튼을 가로 행으로 표시하고 모바일에서는 세로로 배치한다. 판매액·재고 통계와 집중 라벨은 제거하며 선택된 행사만 체크·파란 강조로 표시한다. 일정 없는 행사는 추정하지 않는다.
- 행사 등록은 상단 행사 목록·새 행사 추가 탭을 사용한다. 관리 가능한 행사의 더보기는 명시적 projectId를 가진 행사 관리 링크와 구성 가져오기 버튼을 제공한다.

## 공통 표현과 실행 경계

탭은 구매 방식과 동일한 글꼴·높이·선택 밑줄을 재사용한다. 모바일 상위 메뉴는 판매·행사 목록·내 재고관리·더보기를 펼침 없이 가로로 배치한다. 재고·등록·판매내역은 1120px, 행사 판매현황은 1440px, POS 판매 목록은 최대 너비 제한 없이 표시한다. 화면 표현 수정은 공통 폰트·테이블 헤더 가운데 정렬을 유지한다.

운영 DB 적용·배포와 브라우저/모바일 실기기 확인은 로컬 테스트와 별개다. 온라인 판매 입력은 아직 저장하지 않는다.


## 행사 전환·조회 상태·웹 분석

헤더 행사명은 행사 변경 선택기로 행사명·부스·일정·상태·현재 선택과 전체 행사 보기 링크를 제공한다. 판매 메뉴와 로고는 현재 행사의 기본 화면으로 이동한다. 판매 또는 명시적인 상품 조회 권한이 있으면 판매/조회 화면, 본인 내역·정산 권한만 있으면 판매현황으로 이동하고 미선택/접근 불가는 행사 목록으로 이동한다. 마감·보관 행사는 기존 읽기 전용 화면을 유지한다.

상단 확인 항목은 회수 필요→배정 가능→확정 정산 대기→마감된 마이너스 정산 순이다. 미마감 마이너스 정산을 확정 경고로 표시하지 않는다. 품절 임박과 미동기화 확인 항목은 특정 집중 행사에 한정하지 않고 조회 범위에서 표시한다. 비용 상세가 없는 값은 역산하지 않는다. 미동기화 거래는 이 기기의 현재 계정/행사 귀속이 확인된 주문만 집계한다.

GET /api/* 조회는 requestJson에서 JSON 처리 완료까지 집계한다. 150ms 이상 지속하면 중앙 ‘불러오는 중…’ 스피너를 표시하고 오류/취소도 해제한다. POST 판매·저장·자동 동기화는 제외하며 열린 dialog 내부 조회는 해당 dialog에 표시한다.

Vercel Analytics는 프로덕션 웹만 사용한다. React 컴포넌트의 route/path는 승인된 hash 화면의 고정 pagePaths를 전달하며 행사/상품 ID·URL 쿼리·금액 사용자 정의 이벤트는 보내지 않는다. 실제 수집은 Web Analytics 활성화와 배포 후 확인해야 한다.

마지막 행사는 localStorage의 `pos_last_event:<Vite mode>:<계정 ID>`에 ID·부스 ID만 저장한다. 복원은 현재 계정의 접근 가능한 workspace 후보와 ID·부스가 일치할 때만 허용하며, 로그아웃 후에도 계정별 환경설정을 유지한다. 기존 집중 행사 저장값과 구형 공통 선택 키는 복원하지 않는다. 기기 간 동기화나 인증 세션 지속 저장 확대는 없다.

로그인 후 기본 진입/빈 경로는 복원한 행사의 권한별 기본 화면, 복원 불가는 행사 목록으로 이동한다. 명시적인 URL·인증 전 딥링크·새로고침·뒤로/앞으로의 목적지와 projectId 쿼리를 유지한다. 날짜만으로 다른 행사를 선택하지 않는다. 행사 전환은 기존 작성 중 확인을 재사용하며 장바구니도 보호한다. 수락한 전환은 이전 응답 적용을 막고 화면 투영을 초기화하며 IndexedDB 주문·localOrderId·서버 데이터는 변경하지 않는다.
