# Codex 개발 하네스

Codex가 작업 전에 확인할 문서는 이 디렉터리에 모은다. 저장소 루트의 `AGENTS.md`는 자동으로 읽히는 진입점으로 유지한다.

## 읽는 순서

1. [작업 지침](../../AGENTS.md): 변경 범위, 데이터 보호, 로컬 작업 및 PR 정책.
2. [구조와 계약](architecture.md): 구현 경로와 데이터·API 계약.
3. [위험과 개선 순서](risks.md): 남아 있는 위험과 개선 우선순위.
4. [검증 절차](validation.md): 해당 작업의 시나리오와 기존 검증 이력.

[오프라인 우선 계획](offline-first-plan.md)은 계획과 구현 여부를 구분해 읽고, [기본 상품 이미지](default-product-image.md)는 이미지 변경 시 참고한다. Android 작업은 [Android 문서](../android.md)도 확인한다.

## 디자인·레이아웃 요청의 빠른 처리

디자인·레이아웃만 바꾸는 요청은 수정 후 바로 결과를 전달한다. 테스트 작성·실행, 빌드, 브라우저 자동화·스크린샷 검증과 검증 시나리오는 생략하고, 이를 위한 의존성 설치나 환경 구성도 하지 않는다. 사용자가 검증을 명시적으로 요청하면 요청 범위만 수행한다. 기능·데이터 계약도 바꾸는 작업은 해당 기능의 기존 검증 기준을 따른다. 상세 적용 범위는 [작업 지침의 완료 기준](../../AGENTS.md)을 따른다.

## 기존 디자인을 유지하는 화면 변경

작가 중심 구조의 새 화면이나 기존 화면의 디자인을 정리할 때는 [기존 디자인 적용 하네스](design-continuity.md)를 먼저 읽는다. 기존 화면 대응표·디자인 기준 버전·기능 보존 범위·단계별 로컬 확인 절차를 따른다. 디자인 참고를 위해 예전 데이터 조회나 권한 로직을 복원하지 않는다.

## 모바일·데스크톱 공통 폰트

새 화면과 기존 화면 수정은 [공통 폰트 규격](../../AGENTS.md#공통-폰트-규격-2026-10-22)을 따른다. 같은 역할의 컴포넌트는 모바일·데스크톱에서 동일한 크기·굵기·줄 높이를 사용하며 `/inventory` 검색 조건의 공통 폰트 토큰을 재사용한다. 반응형 배치는 여백·줄바꿈·너비·스크롤로 조정하고, 미디어 쿼리의 폰트 축소·확대 및 토큰 재정의는 제거한다. 제목과 주요 수치는 역할별 공통 규격을 유지한다.

## 로컬 디렉터리 운영

- 실제 프로젝트는 저장소 루트의 `src`, `api`, `public`, `android`, `scripts`, `tests`다. 원격 `main`을 로컬 기준으로 사용한다.
- `.codex-*`는 과거 PR의 별도 Git worktree였으며 독립 프로젝트가 아니다. 새 작업은 기본 작업 폴더에서 진행하고, 별도 worktree가 필요하면 저장소 내부에 중첩하지 않는다.
- 정리 전 `git status`, `git diff`, `git worktree list`와 PR 상태를 확인한다. 미커밋 변경을 보존하고 종료된 PR의 브랜치만 제거한다.
- `.local-archive/`는 Git에서 제외하는 로컬 복구 자료다. 환경변수 파일과 `node_modules`는 하네스에 복사하지 않는다.

기존 구조·위험·검증 문서는 날짜별 이력을 포함한다. 최신 기록과 현재 코드를 함께 확인하고, 과거 기록을 현재 지원 기능으로 단정하지 않는다.

## 작가·부스 구조 전환

최신 상태(2026-10-22 후속): 05는 제외했다. 사용자 기기 확인 후 기존 admin 부스의 [06 실제 구형 쓰기 종료·보존 대조](../artist-booth-transition/06-data-retirement.md)를 완료했다. 저장 열·별칭 삭제와 앱 배포는 하지 않았다. [메뉴 재배치 가이드](../artist-booth-transition/07-navigation-and-permissions.md)는 제안 단계이며 행사별 대리 권한/메뉴 구현이 필요하다. 이 기록을 현재 상태로 따른다.

[진행 현황](../artist-booth-transition/README.md), [02 구현·검증 경계](../artist-booth-transition/02-implementation.md), [03 작가 연결](../artist-booth-transition/03-implementation.md)을 확인한다. 02의 기존 실제 자료 이관과 03/04 로컬 구현·격리 검증을 완료했다. [04 직접 재고 관리](../artist-booth-transition/04-implementation.md)의 추가 지침(승인/예약 제거·행사 기간 운영자 전용)이 초기 설계보다 우선한다. 실제 작가 계정 연결·03 실환경 경쟁·배포를 완료한 것은 아니다. 서비스는 운영 전이며 동시 운영 검증은 공개 전 별도 범위다. 명시적 이관 전후의 권한·백업/복원·큐 계약을 구분하고, 실환경 미실행 검증을 완료로 간주하지 않는다.

## IndexedDB 우선 데이터 기능 변경

조회·저장·수정·삭제를 추가하거나 수정할 때는 [공통 데이터 계층 하네스](local-first-data.md)의 범위 키·업무 어댑터·온라인/큐 정책·충돌 규칙을 따른다. 행사 목록/POS 우선 조회와 공통 큐 기반 구현을 전체 기능 전환 완료로 해석하지 않는다.

## 행사 운영자 재고 정책 후속 (2026-10-23)

[운영자의 작가 재고 관리 정책](../artist-booth-transition/inventory-management-policy.md)을 03 계정/연결과 04 재고 작업 전에 읽는다. 총재고 하한·기본 허용/해제·참여 부스 한정 위임·판매/취소 유지·변경 이력의 최신 지침이다. 신규 설정·확인된 참여 관계에 따른 서버 강제와 행사 상세 수량 편집은 로컬 구현했다. [04 구현 기록](../artist-booth-transition/04-implementation.md)과 검증 절차의 최신 기록을 따른다. 운영 DB 적용·배포·실기기 검증은 별도다.


## 필수 검증 범위 (2026-10-28)

검증은 [필수 검증 선택 기준](validation.md#필수-검증-선택-기준-2026-10-28)에 따라 변경 동작과 직접 영향을 받는 보존 계약만 확인한다. 문서·주석만 변경하면 내용·링크·diff만 확인하고, 디자인·레이아웃만 변경할 때는 기존 검증 생략 규칙을 유지한다. 기능 변경은 필요한 테스트 항목만 선택하며 프런트엔드 기능/번들 변경에만 빌드를 추가한다. API/DB 전용 변경에 프런트 빌드나 전체 테스트를 자동으로 붙이지 않는다. 전체 테스트로 확대하거나 통과한 검증을 반복하려면 실제 영향·실패 등 구체적 근거를 기록한다. 과거 검증 기록의 실행 건수는 현재 작업의 최소 실행량이 아니다.
