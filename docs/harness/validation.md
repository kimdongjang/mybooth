## 환경과 실행

- `npm ci`는 잠금파일 기준 설치, `npm run dev`는 5173 고정 포트의 Vite + 로컬 API 미들웨어다.
- `npm run build`는 정적 프런트 빌드다. 서버 함수, DB 접근, 타입 검사, 브라우저 오프라인 동작을 확인하지 않는다.
- `npm run preview`는 빌드 정적 화면 확인용이다. configureServer의 API 미들웨어는 실행되지 않는다.
- 개발 API는 `process.env`를 읽는다. 현재 vite.config.js에 `loadEnv`/dotenv 주입이 없어 `.env.local`만 생성해서는 API 환경변수를 보장하지 않는다. 터미널의 프로세스 환경 또는 환경을 주입하는 실행 도구를 사용한다.
- Git 소유권 오류가 발생하면 환경에 맞게 처리한다. 이번 분석은 전역 설정을 변경하지 않고 `git -c safe.directory=D:/01-work/99-repository/pos-system/pos_system …`을 사용했다.

| 변수 | 실제 용도 |
| --- | --- |
| POSTGRES_URL | 설치된 `@vercel/postgres` sql pool의 기본 연결. 별도 개발/검증 DB 사용 |
| AUTH_SECRET | 토큰 HMAC 서명. 환경별 별도 값으로 설정, 공개 예시 값 사용 금지 |
| BLOB_READ_WRITE_TOKEN | Public Vercel Blob의 서버 전용 토큰. 이미지 직접 업로드 토큰 발급에 사용; VITE_에 넣지 않음 |
| ADMIN_ID / ADMIN_USERNAME | ADMIN_PASSWORD가 있을 때 초기 관리자 ID; 기본 admin |
| ADMIN_PASSWORD | 초기 관리자 등록 및 AUTH_SECRET 미설정 시 서명 fallback; 기존 계정 비밀번호 변경 기능 아님 |

`.env.example`은 변수 안내용이다. 실제 비밀번호/연결 문자열을 커밋하거나 문서에 복사하지 않는다. 예시 AUTH_SECRET은 운영 비밀로 사용하지 않는다. DATABASE_URL만 설정한 경우 코드의 사전 검사가 통과해도 실제 sql pool은 연결하지 못할 수 있다.

## Vercel 배포 확인 항목

아래는 저장소 구조에서 도출한 확인 절차다. 실제 Vercel 설정이나 현재 플랫폼 정책을 확인한 배포 기록이 아니다.

1. 배포 루트에 package.json, index.html, api/가 있는지 확인한다. 프런트 빌드 명령 `npm run build`, 출력 `dist`와 서버 함수 `/api/auth`, `/api/pos`의 노출을 확인한다.
2. Preview와 Production 환경의 POSTGRES_URL/AUTH_SECRET을 각각 확인한다. Preview 검증은 운영 DB와 분리한다.
3. 배포 후 테스트 계정 가입/로그인 → 프로젝트 생성 → 상품 조회 → 판매 → 서버 재고/판매 재조회 순으로 확인한다.
4. 기존 DB의 project_id/상품 컬럼/키 보완은 요청 초기화에서 실행한다. Preview의 별도 DB에 기존 스키마를 복제하여 생성/반복 요청을 검증하고, 운영 적용 전 백업과 ALTER 권한을 확인한다. 과거 NULL 행은 admin의 7월 서코행사에 자동 연결한다. 적용 전 백업과 동일 ID 충돌 여부를 확인한다.
5. 서비스 워커 설치와 정적 자산 캐시를 확인하고 네트워크 차단/복구 시나리오를 수행한다.
6. 실제 배포 URL, 커밋/작업 트리, 실행일, 검증 DB 식별자, 시나리오 결과를 기록한다. secret은 기록하지 않는다.
