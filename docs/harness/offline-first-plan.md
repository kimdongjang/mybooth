# 네트워크 불안정 대응: IndexedDB 우선 저장 작업 계획

작성일: 2026-10-15. 이 문서는 합의한 운영 정책과 구현할 작업을 정리한다. 체크되지 않은 항목은 미구현 또는 검증이 필요한 작업이며, 현재 지원 기능을 뜻하지 않는다. 코드 점검 기준은 작성일의 원격 main이다.

## 목표와 운영 정책

온라인에서 인증한 계정의 행사 데이터를 기기에 준비하고, 이후 조회와 현장 변경은 IndexedDB를 기준으로 처리한다. 서버 연결이 복구되면 미전송 변경을 올리고 원격 변경을 내려받아 병합한다. 서버 응답으로 미전송 로컬 변경을 덮어쓰지 않는다.

| 기능 | 목표 정책 |
| --- | --- |
| 회원가입·로그인 | 온라인 API 필수. 오프라인 제출 차단 및 API 실패 안내 |
| 로그인 유지 | 명시적 로그아웃 전까지 브라우저 재시작 후에도 유지. 서버 인증 무효화는 온라인에서 확인하고 재인증 요구 |
| 최초 데이터 준비 | 로그인 계정 ID, 전체 행사 목록, 행사별 상품·세트·재고·판매·보관 상태·리비전을 내려받아 로컬 저장 |
| 조회·정산 | 준비된 로컬 데이터로 즉시 제공 |
| 판매·취소 | 로컬 원자 저장 후 전송 대기, 연결 시 서버 반영 |
| 상품·세트·입고·재고 관리 | IndexedDB 우선 변경 및 명령 큐 도입 대상. 원격 충돌 규칙 마련 후 오프라인 허용 |
| 행사 삭제·보관·보관 해제 | 온라인 전용, 서버 소유권 및 비밀번호 확인 유지 |
| 스냅샷 파일 백업·복원 | 오프라인에서도 자유롭게 실행. 서버 관리 작업과 별도 기능 |
| 로그아웃 | 해당 계정의 모든 행사에 미동기화 판매·취소가 있으면 차단. 관리 명령 큐 도입 시 해당 변경도 포함 |

저장 범위는 해당 기기의 해당 브라우저·사이트다. 다른 기기/브라우저로 자동 공유되지 않으며, 사이트 데이터 삭제·시크릿 모드·저장소 부족에 대한 영구 보존은 보장할 수 없다. 여러 기기의 오프라인 판매는 실시간 공유 재고를 보장하지 않는다.

## 현재 구현과 차이

- `src/database/dexie.ts`: 프로젝트별 `orders`, `posState`만 존재한다. 계정별 행사 목록, 지속 세션, 준비 진행 상태, 관리 변경 큐는 없다.
- `src/App.jsx`: 가입/로그인과 행사 목록/관리는 API를 직접 호출한다. 인증/선택 행사는 sessionStorage에 저장한다. 상품·세트·입고·조정은 `mutate`로 서버 성공 후 캐시를 갱신한다.
- 판매는 주문 큐에 먼저 기록하지만 상태 스냅샷은 별도 비동기 저장이다. 취소도 상태와 큐를 따로 저장한다.
- `src/hooks/useSync.ts`, `src/sync/syncService.ts`: 열린 앱에서 현재 선택 행사 주문을 시작 시/10초 주기/연결 복구/수동/판매 직후 전송한다. 전체 계정의 양방향 동기화나 앱 종료 후 백그라운드 전송은 없다.
- `src/database/orderRepository.ts`: PENDING/FAILED만 재전송하므로 앱 종료 후 남은 SYNCING 복구가 없다. 서버 응답 상태 병합도 없다.
- `loadState`는 온라인 서버 응답으로 로컬 상태를 교체하여 미전송 판매 효과가 화면에서 사라질 수 있다. 오프라인 재시작도 행사 목록 API에 의존한다.
- 기존 `backupProject`/`restoreProject`는 비밀번호 확인이 필요한 온라인 서버 백업/새 행사 복원이다. 주문 큐 JSON/CSV 내보내기도 전체 로컬 스냅샷 복원 기능은 아니다.

## 구현할 작업

### 1. 로컬 저장·판매 복구 기반 (우선)

- [ ] IndexedDB 스키마에 계정/행사 범위를 명시하고 기존 DB 마이그레이션을 구현한다. 계정 전환 시 다른 계정의 데이터·큐를 읽거나 전송하지 않는다.
- [ ] 판매·취소의 주문 큐와 재고·판매 상태를 하나의 IndexedDB 트랜잭션으로 저장한다. 저장 성공 후 완료 UI를 표시하고 실패 시 변경을 남기지 않는다.
- [ ] 전송 도중 종료된 SYNCING 명령을 안전하게 회수한다. 여러 탭 전송 조정과 서버 멱등성으로 중복 효과를 방지한다.
- [ ] `localOrderId`/명령 ID를 재시도 때 유지한다. 응답 유실·동시 요청·취소 후 원 판매 재전송에도 재고가 한 번만 변하도록 서버 기록을 보존한다.
- [ ] 서버 기준 상태와 미전송 명령을 분리하고, 서버 갱신 후 미전송 명령을 재적용해 표시 상태를 구성한다. 재고·판매 효과의 이중 적용을 막는다.
- [ ] 판매 시점 상품/세트 구성·가격·제작자 스냅샷을 보존한다. 무료 판매와 정수 가격/수량 검증을 유지한다.

### 2. 지속 세션과 오프라인 사용 준비

- [ ] 가입·로그인 폼의 오프라인 제출을 차단한다. navigator.onLine뿐 아니라 API 실패/지연도 처리한다.
- [ ] 지속 세션 복원 경로를 마련한다. 비밀번호를 로컬에 저장하지 않으며, 세션 저장 방식과 서버 무효화/재인증 처리를 설계한다.
- [ ] 로그인 계정의 전체 행사 목록과 행사별 상품·세트·재고·판매·보관 상태·리비전을 일괄 다운로드한다. 큰 데이터는 페이지/배치로 내려받더라도 전체 준비 여부를 추적한다.
- [ ] 행사별 진행 상태와 준비 버전을 저장한다. 데이터가 같은 기준으로 완전히 저장된 경우에만 ‘오프라인 사용 준비 완료’를 표시한다.
- [ ] 중단·실패 시 ‘다시 불러오기’ 버튼을 제공한다. 준비된 행사와 실패한 행사를 구분하고, 재시도 시 기존 정상 데이터와 미전송 변경을 보존한다. 불완전한 새 버전은 기존 정상 버전을 대체하지 않는다.
- [ ] 앱 재시작 시 로컬 세션·행사 목록·선택 행사·상태부터 복원한다. 준비되지 않은 행사는 온라인 다운로드가 필요함을 표시한다.
- [ ] 정적 앱 캐시와 상품 이미지 캐시를 구분한다. 이미지 다운로드 실패가 거래 데이터 준비 상태에 미치는 기준과 대체 표시를 정한다.

### 3. 계정 전체 동기화와 관리 변경

- [ ] 현재 선택 행사와 무관하게 로그인 계정의 전체 행사 큐를 순회한다. 프로젝트별 순서와 의존성을 지키고 요청 시작 시 계정/토큰/프로젝트를 고정한다.
- [ ] 시작/주기/복구/수동 실행에 업로드와 원격 변경 수신을 함께 연결한다. 열린 앱에서만 주기 실행됨을 UI와 문서에 명시한다.
- [ ] 요청 타임아웃, 재시도 간격, 인증 실패·입력 오류·충돌·서버 장애 구분을 구현한다. 재시도 불가능한 변경을 무한 전송하지 않고 원인/해결 방법을 표시한다.
- [ ] 상품·세트 변경, 입고·조정을 로컬 상태와 함께 원자 저장하는 명령 큐로 전환한다. 전체 목록 교체 대신 개별 명령/버전 검사로 다른 기기의 변경을 보존한다.
- [ ] 이미지 바이너리의 로컬 보관·업로드 재시도·상품 등록 후 연결 순서를 구현한다. URL만 저장해서 오프라인 업로드가 완료된 것으로 취급하지 않는다.
- [ ] 행사 생성의 오프라인 허용 여부와 로컬 ID→서버 ID 매핑을 별도 확정한다. 삭제·보관·보관 해제는 온라인 전용으로 유지한다.
- [ ] 원격 보관·삭제·리비전 변경과 로컬 미전송 명령이 충돌하면 보존하고 해결을 안내한다. 단순 재시도로 유실·재생성이 발생하지 않도록 한다.

### 4. 로그아웃과 계정 격리

- [ ] 현재 계정의 모든 행사에서 PENDING/FAILED/SYNCING을 조회한다. 하나라도 있으면 로그아웃을 차단한다.
- [ ] ‘서버에 보내지 않은 내역이 N건 있습니다. 동기화 완료 후 로그아웃할 수 있습니다.’와 ‘동기화 재시도’/‘계속 사용’을 제공한다. 오프라인에서는 연결 후 재시도하도록 안내한다.
- [ ] 로그아웃 검사와 새 변경 생성/진행 중 동기화의 경쟁을 막는다. 확인 후 새 명령이 추가된 상태에서 인증/캐시를 지우지 않는다.
- [ ] 정상 로그아웃 시 지속 인증 정보를 제거한다. 계정 캐시 정리 정책을 명시하고, 미전송 변경이 있으면 지우지 않는다. 서버가 인증을 거절해도 큐를 보존하고 동일 계정 재인증으로 복구한다.

### 5. 오프라인 스냅샷 백업·복원

- [ ] IndexedDB의 일관된 읽기 스냅샷에서 행사 정보·상품·세트·재고·판매·모든 명령 상태를 파일로 내보낸다. 생성 시각, 형식 버전, 원본 계정/행사 식별자, 리비전을 포함한다.
- [ ] 인증 토큰·비밀번호·서버 비밀은 제외한다. 이미지 포함 여부와 용량 제한을 명시하고, URL만 보관할 경우 오프라인 이미지 한계를 표시한다.
- [ ] 온라인 비밀번호 확인 없이 파일을 검증하고 별도 로컬 복원본으로 원자 저장한다. 손상·중복 ID·잘못된 가격/수량·지원하지 않는 버전은 거절하며 기존 행사/큐를 덮어쓰지 않는다.
- [ ] 백업에 포함된 미전송/완료 명령은 복원본의 참고 기록으로 보존한다. 실행 큐로 자동 복원하거나 기존 주문을 자동 전송하지 않는다. 복원본은 원격 원본과 분리된 ID/상태를 사용한다.
- [ ] 복원본을 온라인에서 새 행사로 등록하는 명시적 절차를 마련한다. 파일의 계정/행사 ID를 권한으로 신뢰하지 않고 서버에서 소유권·내용을 검증한다. 등록 요청 자체도 재시도 시 중복 행사가 생기지 않게 한다.
- [ ] 기존 서버 백업/복원 및 주문 큐 내보내기와 새 로컬 스냅샷을 UI에서 구분한다. 로컬 파일 백업과 서버 행사 보관은 서로 다른 작업임을 표시한다.

## 구현 전에 확정할 세부 정책

다음은 합의된 기능 범위 안에서 추가 설계가 필요한 항목이다.

- 오프라인 다중 기기의 초과 판매, 동시 상품 수정, 원격 삭제/보관 충돌을 어떻게 해결할지.
- 지속 세션의 저장·무효화 방식, 정상 로그아웃 시 로컬 캐시 삭제 범위.
- 오프라인 신규 행사 생성 허용 여부, 최초 준비 중 일부 행사만 성공했을 때의 이용 범위.
- 스냅샷 이미지 포함 방식, 파일 크기/버전 정책, 복원본의 판매 허용 시점과 새 행사 등록 시 과거 판매/재고 처리 기준. 복원된 과거 거래를 새 판매 명령으로 재실행하지 않는 원칙은 유지한다.

## 검증 및 완료 기준

운영 DB를 사용하지 않고 별도 DB·브라우저 프로필에서 수행한다. 아래는 향후 합격 기준이며 이번 문서 작업에서 실행한 테스트가 아니다.

| 시나리오 | 확인할 결과 |
| --- | --- |
| 가입·로그인 중 단절/API 장애 | 제출 제한 또는 실패 안내, 잘못된 세션 생성 없음 |
| 로그인 후 전체 데이터 준비/중간 단절/재시도 | 준비 완료 표시는 완전 저장 후에만 표시, 기존 데이터·큐 보존 |
| 브라우저 종료 후 오프라인 재시작 | 세션/행사 목록/선택 행사/상품/판매 복원, API 없이 준비된 행사 이용 |
| 판매·취소 저장 중 실패/종료 | 큐·재고·판매가 모두 반영되거나 모두 미반영 |
| 전송 응답 유실/SYNCING 중 종료/다중 탭 재전송 | 복구 가능, 서버 판매·재고 효과 한 번만 적용 |
| 미전송 상태에서 새로고침/원격 변경 수신 | 미전송 판매·재고 효과 유지, 서버 적용분 이중 계산 없음 |
| 선택하지 않은 행사에 대기 주문 | 해당 계정 전체 동기화 및 로그아웃 차단 |
| 다른 계정 로그인/요청 중 계정 전환 | 데이터 조회/전송 혼합 없음, 서버 소유권 검사 유지 |
| 오프라인 관리 편집 후 연결 | 변경 순서/충돌 처리, 무료 상품·세트·입고·재고 정합성 유지 |
| 행사 삭제·보관·해제 오프라인 시도 | 요청 차단, 온라인 서버 비밀번호 검증 유지 |
| 오프라인 파일 백업/복원/손상 파일 | 전체 스냅샷 보존, 손상 거절, 기존 데이터 유지, 자동 원격 전송 없음 |
| 같은 스냅샷 반복 복원/새 행사 등록 재시도 | 기존 서버 판매 중복 반영 없음, 등록 요청 중복 방지 |
| 저장소 부족/캐시 갱신/이미지 실패 | 저장 실패 명시, 거래 유실/거짓 준비 완료 없음 |

기존 [검증 절차](validation.md)의 SALE/VOID/IDEM/RACE/TX/OFF/SWITCH/CACHE 시나리오를 함께 보완한다. 구현 PR마다 관련 자동화·브라우저·별도 DB 검증과 `npm run build` 결과를 기록한다. 빌드는 타입 검사나 API/DB·오프라인 통합 테스트를 대신하지 않는다.

## 관련 문서와 수정 경로

- [현재 구조와 계약](architecture.md), [위험과 개선 순서](risks.md), [검증 절차](validation.md)
