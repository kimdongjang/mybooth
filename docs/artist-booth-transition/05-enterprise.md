## 시작 조건

04까지의 공통 소유권·재고·판매 계약이 완료되어 있어야 한다. [04 구현 기록](04-implementation.md)의 직접 관리·기간별 운영자 전용 정책이 초기 납품 승인 설계보다 우선한다. `api/lib/artistStock.js`의 현재 프로필/소유자 접근과 보관 계정 결정을 조직 소유자로 확장하며 별도 재고 엔진을 만들지 않는다.

## 이번 작업 범위

조직 소유자와 부스 유형에 따라 화면·기본값을 정리한다. 별도의 판매/재고 엔진은 만들지 않는다.

한 번의 작업에서는 아래 항목 중 완료 가능한 묶음을 선택하고 나머지는 미완료로 남긴다. 다른 단계 구현은 현재 작업에 섞지 않는다.

## 상세 TODO

- [ ] 부스 유형을 협업/기업으로 저장하고 유형 변경 시 데이터 삭제 없이 메뉴·기본값을 변경한다.
- [ ] 기업 조직을 기본 재고 소유자/수취인으로 사용하고 기업 사용자 여러 명의 운영 권한을 제공한다.
- [ ] 기업 화면에서 작가 초대·작가별 위탁/분배 메뉴를 숨기고 상품·행사 매출·원가·재고 중심으로 표시한다.
- [ ] 기업도 필요하면 외부 작가 위탁을 켤 수 있게 한다. 화면에서 숨김과 서버 권한 검사는 별개로 유지한다.
- [ ] 작가/부스 문맥 전환, 라우팅, 뒤로/앞으로, 미저장 보호, 로딩·오류 처리를 연결한다.
- [ ] 공통 폰트 토큰을 재사용하고 불필요한 안내·반복 성공 알림·빈 상태 요소는 추가하지 않는다.

완료 조건: 동일한 판매/재고 엔진으로 협업 부스와 기업을 운영하고, 유형 변경만으로 소유권·정산 이력이 바뀌지 않는다. 실제 손익 표시는 원가/비용 귀속 정책이 확정된 범위에서만 제공한다.

## 검증과 다음 단계 진입 조건

- [ ] 협업/기업 유형 전환 전후 수량·정산·소유권이 유지되는지 확인한다.
- [ ] 조직 관리자 권한과 외부 작가 위탁 허용 범위를 검증한다.
- [ ] 화면에서 숨긴 메뉴도 서버 권한 검사를 유지하는지 확인한다.
- [ ] 문맥 전환·미저장 보호·공통 폰트 규격을 확인한다.

공통 기준 중 이번 변경에 해당하는 검증을 수행한다. 정책 문서 작업은 코드 검증을 완료한 것으로 표시하지 않는다. 기능 구현은 빌드와 관련 테스트, 하네스 시나리오의 통과/기존 실패/미실행을 구분한다. 필수 검증이 미실행이면 이유와 다음 단계 진입에 미치는 영향을 기록하고 미실행 항목을 통과로 간주하지 않는다.

## 작업 결과 기록

- 진행한 작업: 미작성
- 변경 파일·계약: 미작성
- 검증 명령·시나리오와 결과: 미실행
- 남은 정책/실패/미실행 및 영향: 미작성
- 다음 작업의 시작점: 미작성
- 다음 단계 진입 가능 여부와 근거: 미판정
