# 04 직접 재고 관리 구현·검증

2026-10-22. 로컬 구현이며 실제 DB의 7월/12월 재고·계정 연결·행사 일정을 수정하거나 배포하지 않았다. [04 작업 목록](04-consignment.md)과 [현재 정책](policy-baseline.md)이 초기 예약/승인 계획보다 우선한다.

## 사용 흐름

메뉴 **작가 재고**(`/artist-stock`)에서 내 프로필 또는 운영 부스의 참여 작가를 선택한다. 운영자는 미연동 작가도 관리한다. 프로필 생성/미가입 작가 추가·연결은 기존 마이페이지를 사용한다. 작가는 운영자가 전달한 부스 코드로 자기 프로필을 직접 참여시켜 같은 상품을 다른 부스 행사에도 배정할 수 있다. 이 참여는 POS 전체 조회·판매 역할을 부여하지 않는다.

상품 등록에서 행사와 수량 20을 지정하면 작가의 재고 한 행에 20개를 입고하고 그 행사에 전량 배정한다. 작가 총재고와 행사 수량은 같은 재고의 서로 다른 표시다. 기존 상품은 미배정에서 행사로 배정한다. 행사 배정 수량을 줄이면 판매/차감되지 않은 잔량만 미배정으로 돌아온다. 가져올 위치에 다른 행사를 지정하면 회수와 배정을 한 트랜잭션으로 처리한다. 승인/거절/예약/조건 재승인 화면은 없다.

운영자는 행사 시작일·종료일을 저장한다. 작가는 한국 시간의 행사 기간 동안 해당 행사 배정·회수·가격·행사 로스를 변경할 수 없다. 화면 비활성화와 서버 검사를 함께 적용한다. 운영 역할(owner/manager)이 있으면 그 역할로 관리한다. 날짜 미설정 행사는 운영자만 수정하며 행사 이름에서 일정을 추측하지 않는다. 개인 미배정 입고/정정은 행사 수량을 바꾸지 않는 범위에서 유지한다.

## 원본과 동시성

기존 `pos_inventory`가 상품별 미배정 수량의 기준이다. `pos_inventory_owners`의 영구 소유자에 연결하고 `pos_inventory_links`로 서로 다른 보관 계정의 행사에서도 같은 원본을 참조한다. 원본 상품을 부스별로 복제하거나 기존 거래를 다시 만들지 않는다. 새 상품의 보관 계정은 연결된 작가이며, 미가입 프로필은 기존 출처 부스의 대리 보관 계정을 유지한다.

`pos_shared_stock_items`는 기존 행의 식별 매핑이며 별도 잔량을 갖지 않는다. 조회로 재고를 재입고하지 않는다. 전역 집계는 해당 상품의 연결 행사들만 읽고, 참여 부스 운영자에게는 다른 부스의 상세 배정/행사 ID/판매를 반환하지 않는다. 관리 총재고와 현재 잔량·누적 입고를 구분한다. 알려진 미배정 파손/분실/외부 차감도 관리 기준량 대조에 보존한다.

수량 작업은 호출자·작가/원본 보관 계정·대상 행사 보관 계정의 정렬 잠금, 행사/소유자/원본 행 잠금, 반복 읽기 트랜잭션과 version을 사용한다. 기존 POS 판매/취소도 공유 상품의 원본 보관 계정을 먼저 잠근다. 미배정/행사 잔량 이상 배정·회수는 거절하고, 충돌은 409로 반환한다. 원본의 구형 쓰기 경로는 작가 재고 화면으로 유도해 전역 집계를 우회하지 못하게 한다.

변경과 `pos_shared_stock_commands` 영수증은 함께 커밋/롤백한다. 원장은 요청 ID·실제 작성자·소유자·부스/행사·변경 전후 값을 남긴다. 동일 요청의 재확인은 수량을 다시 움직이지 않고, 같은 ID의 다른 내용은 거절한다. 화면에서 응답 유실 시 편집을 잠그고 같은 요청만 재확인한다. 연속 제출은 즉시 잠금으로 차단하며 자기/운영 범위의 변경 이력도 표시한다.

## API

모두 인증된 `/api/booths`를 사용한다. POST는 `{action,payload}`이며 변경마다 UUID requestId가 필요하다. stockId는 원본 계정/상품의 불투명한 고정 식별자이고 이름으로 다른 작가 상품을 병합하지 않는다.

| 요청 | 주요 payload / 결과 |
| --- | --- |
| GET `?artists=stock&ownerId=…&boothId=…` | 작가 상품·미배정/전역 수량·허용된 배정/행사·일정·참여 상태. 본인은 boothId 생략 가능 |
| `createArtistStock` | ownerId, 선택 boothId/projectId, name, price, quantity. 새 입고와 선택 행사 배정을 함께 반영 |
| `adjustArtistStock` | ownerId, id, version, totalStock, reason receipt/correction. 행사 초기 배정·알려진 차감 아래로 감소 금지 |
| `setArtistAllocation` | ownerId, id, version, projectId, quantity(행사 초기 배정), 선택 price. source 지정 시 fromProjectId/moveQuantity 추가 |
| `recordArtistStockLoss` | ownerId, id, version, quantity, reason damage/loss/external, 선택 projectId. 외부 판매는 미배정 위치만 |
| `saveEventStockSchedule` | boothId, projectId, startsOn, endsOn. 해당 부스 owner/manager만 저장 |
| `joinArtistBooth` | ownerId, boothId. 작가 본인이 자기 재고 관리 관계를 직접 추가 |
| `leaveArtistBooth` | ownerId, boothId. 본인 또는 운영자. 미반환/미정산이면 ending, 정리 후 재확인하여 ended |

행사 권한 검사는 서버 `clock_timestamp()`의 Asia/Seoul 날짜로 수행해 잠금 대기 중 자정이 지나도 브라우저 시각/거래 시작 시각으로 우회하지 못하게 한다. 운영 종료·정산 마감은 기존 제한을 유지하며 보관 행사의 신규 배정은 거절한다.

## 판매·취소·파손·종료

행사 판매는 기존 서버 상품 재고를 차감한다. ownerId/recipientId/고정 정산 별칭은 서버 매핑으로 결정하고 기존 이름·가격·세트 구성 스냅샷과 원 단위 정산 계산을 유지한다. 재고 이동 때문에 누적 입고·매출·확정 정산을 바꾸지 않는다.

예: 100개를 A 40/B 20에 배정하면 미배정 40이다. B 5개 판매 후 잔량 합은 95이며 총재고는 100이다. B의 미판매 15개를 회수하면 미배정 55, B의 초기 배정 5/잔량 0이 된다. 판매 취소는 B에 5개를 복원하며 미배정에 또 가산하지 않는다. 정산 마감 시 취소/배정은 거절한다.

파손·분실·외부 판매는 기존 `pos_stock_movements`에도 소유자/위치/수량을 기록한다. 매출·송금·정산 차감이나 책임 판정은 자동 생성하지 않는다. 행사 로스는 기간 중 운영자만 입력한다. 참여 종료 후 신규 판매는 서버에서 거절하고 미전송 큐는 삭제하지 않는다. 이미 반영된 동일 판매의 재전송은 기존 영수증으로 중복 차감하지 않는다.

종료 정리 중에도 작가 본인 열람은 유지한다. 잔여 회수는 허용하되 새로운 대리 총재고 수정/배정은 거절한다. 미정산 판정은 보수적으로 수행하므로 미마감 판매가 있는 행사는 정산 마감/지급을 정리한 뒤 종료를 재확인한다. 작가 소유권이나 과거 비용 분담 단위를 합치지 않는다.

## 브라우저·백업

같은 기기의 알려진 행사 대기 주문을 재고 변경 전에 차단한다. 선택 행사 상태를 기존 acceptRemote/큐 버전 검사로 반영하고 장바구니를 비운다. BroadcastChannel은 변경 행사 ID만 통지하며 각 탭이 자기 인증으로 다시 조회한다. IndexedDB 스키마와 기존 payload/localOrderId는 변경하지 않는다. 다른 기기의 미전송 주문은 서버가 조회할 수 없으며 늦은 판매가 재고/참여/마감 조건을 위반하면 큐를 보존한 채 거절한다.

부스 v2 백업에 일정/공유 매핑/원장을 보존하고 다른 부스의 배정 상세는 다시 거른다. 보관 계정이 다른 원본은 이름·기본 가격·수량·소유 매핑만 부스 범위로 보존하며 다른 작가 원가를 복사하지 않는다. 직접 부스가 없는 작가 보관 계정도 공유 매핑/소유 관계/자기 원장을 v2에 포함한다. 공유 자료의 전체 교체 복원·삭제는 서버에서 차단한다. 이 파일은 다른 부스 자료까지 독립 복원하는 완결된 스냅샷이 아니며 별도 복구 절차가 필요하다.

- 버전/재시도·부족 수량·명령 원장 실패 롤백 후 동일 요청·파손/분실의 수량 대조와 금전 원장 무변경·구형 우회/복원 거절·종료 후 늦은 판매 거절을 검증한다.
- UI 모형은 당일 작가의 행사 수량/가격 입력 차단과 운영자 허용, 미배정 총재고 유지, 응답 유실 후 동일 요청 ID/내용 재확인을 검증한다.

- 실제 PostgreSQL 다중 연결·부하·교착, 실제 두 계정 브라우저/모바일·다기기 오프라인·배포 캐시는 미실행이다. 운영 DB를 검증에 쓰지 않았다. 실제 자료 변경·서버 재시작·커밋/푸시/배포 없음.

05 기업 모드의 로컬 개발은 진입 가능하다. 공유 재고의 대규모 조회 성능, 다중 부스 생성/운영 문맥 전환, 장기 보관/복구·실제 파기는 별도 후속 범위다.
