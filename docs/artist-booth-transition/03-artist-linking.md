# 03 — 작가 연결과 본인 이력 열람

상태: 완료(로컬 구현·격리 검증). 실제 PostgreSQL 다중 연결·실브라우저·배포 검증은 공개 운영 전 별도 항목으로 남긴다. 실제 작가 계정을 임의 연결하지 않았다.

[진행 현황](README.md) · [공통 계약·검증](common-contracts-and-validation.md)

정책 근거: [01 정책 기준서](policy-baseline.md). 작가가 부스를 만들고 운영하며, 참여 작가와 부스 owner/manager 모두 작가 총재고를 관리한다(P01/P02). 총재고 공동 관리와 타 부스 배정 변경 권한은 구분한다(P04).

## 시작 조건

02가 완료되고 안정적인 프로필·소유자·수취인 ID, 서버 권한과 이력 보존이 검증되어 있어야 한다.

## 이번 작업 범위

작가 프로필 생성, 미연동 프로필 초대·연결, 본인 판매·정산 조회를 구현한다. 재고 납품과 물리 프로필 병합은 제외한다.

한 번의 작업에서는 아래 항목 중 완료 가능한 묶음을 선택하고 나머지는 미완료로 남긴다. 다른 단계 구현은 현재 작업에 섞지 않는다.

## 검증과 다음 단계 진입 조건

- [x] 초대 만료·철회·재사용과 연결 감사 이력을 격리 DB에서 검증한다.
- [ ] 별도 실제 PostgreSQL 다중 연결에서 동시 수락/철회/권한 회수 경쟁을 검증한다. 잠금·반복 읽기 충돌의 409 처리는 구현했으며 PGlite 순차 테스트를 실제 경쟁 통과로 간주하지 않는다.
- [x] 같은 이름의 다른 작가·다른 부스 자료가 노출되지 않는지 검증한다.
- [x] 연결 전후 재고·판매·차감·지급·마감 숫자가 동일함을 확인한다.
- [x] 이름 변경과 여러 프로필 연결 후 본인 귀속 자료만 조회되는지 확인한다.

공통 기준 중 이번 변경에 해당하는 검증을 수행한다. 정책 문서 작업은 코드 검증을 완료한 것으로 표시하지 않는다. 기능 구현은 빌드와 관련 테스트, 하네스 시나리오의 통과/기존 실패/미실행을 구분한다. 필수 검증이 미실행이면 이유와 다음 단계 진입에 미치는 영향을 기록하고 미실행 항목을 통과로 간주하지 않는다.

- 진행한 작업: 마이페이지의 개인 프로필/첫 부스 생성, 미연동 작가 추가, 초대 코드 발급·철회·확인·동의 수락, 본인 판매·취소·비용 귀속·예상/확정 정산·부분 지급·잔액·연결 출처 열람.
- 변경 파일·계약: `api/lib/artistLinking.js`, `api/booths.js`, `api/lib/boothFoundation.js`, `src/components/ArtistAccount.jsx`, `src/pages/AccountPage.jsx`, SW v132. [구현·운영 경계](03-implementation.md)에 API·스키마·수동 확인 순서를 기록했다.
- 검증 명령·시나리오와 결과: 전체 `npm test` 143개 통과. 마지막 보완 후 기반/작가 화면 14개 재확인 및 `npm run build`, `git diff --check` 결과는 구현 기록을 따른다. 초대 동의 UI의 최초 테스트 실패는 비동기 이벤트 완료를 기다리지 않은 모형 문제였고 대기 처리 후 통과했다.
- 남은 정책/실패/미실행 및 영향: 실제 다중 연결·브라우저/모바일·배포 캐시 미실행. 첫 기본 부스 생성만 UI에서 지원하며 여러 부스의 프로필 연결은 지원한다. 다중 부스 생성/작업 부스 전환, 신규 납품, 프로필 병합은 별도 범위다. 공개 운영 전 경쟁 검증이 필요하다.
- 다음 작업의 시작점: 04의 P15 위탁 조건을 구체화하고 소유자 재고와 납품 위치 원장을 연결한다.
- 다음 단계 진입 가능 여부와 근거: 04의 로컬 설계·구현 진입 가능. 승인된 프로필의 본인 조회와 원본 숫자 불변·권한 격리 회귀를 통과했다. 실제 작가 연결·공개 운영 준비 완료를 의미하지 않는다.
