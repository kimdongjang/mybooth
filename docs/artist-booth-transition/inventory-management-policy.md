# 행사 운영자의 작가 재고 관리 정책

2026-10-23 사용자 확정 지침. 작가 → 재고 → 부스 → 행사의 의존 관계를 기준으로 한다. 이 문서는 정책과 구현 기준이며 2026-10-23 후속 작업에서 앱·API·추가 스키마를 로컬 구현했다. 운영 DB에 직접 적용하거나 배포하지 않았다. 아래 규칙은 기존 문서의 무조건적인 운영자 공동 관리 표현보다 우선한다. 사용자가 제외한 원문 3번의 동시 수정 제안은 이번 추가 요구사항에 포함하지 않는다. 기존에 구현된 데이터 보존 장치를 제거하라는 의미는 아니다.

## 상품과 재고의 기준

- 상품과 재고의 소유자는 작가다. 부스는 관리 권한 범위, 행사는 판매·배정 범위다. 같은 상품의 총재고를 부스/행사별로 복제하지 않는다.
- 운영자가 행사에서 새 상품과 수량 20개를 등록하면 선택 작가의 원본 상품/재고를 한 번 만들고 20개를 입고해 현재 행사에 전량 배정한다. 작가 개인 재고에도 같은 상품이 나타나야 한다. 총재고 20개와 행사 배정 20개를 별도 입고로 중복 계산하지 않는다.
- 이미 작가가 등록한 상품은 검색하여 원본 ID를 연결하고 미배정 재고에서 행사로 배정한다. 같은 이름이라는 이유로 상품을 자동 병합하거나 재고를 복사하지 않는다.
- 행사 상품의 제작자/정산 귀속 변경과 원본 재고 소유자 변경은 별도다. 제작자를 바꾸어도 원본 소유권을 자동 이전하지 않는다.

## 총개수와 하한

관리 총개수는 현재 실물 잔량이나 누적 입고와 다르다. 행사에서 이미 판매한 수량도 관리 기준에 남기고 현재 잔량은 별도로 계산한다.

기본 하한은 **각 행사의 현재 배정 기준량 합계**다. 손실 등 별도 차감이 없다면 이는 판매된 수량과 행사에 남아 있는 수량의 합이다. 운영·종료/보관 상태를 이유로 과거 판매분을 제외하지 않는다.

| 예시 | A 행사 | B 행사 | 총개수 최솟값 |
| --- | --- | --- | --- |
| A 종료, B 진행 | 배정 10·판매 10·잔량 0 | 배정 20·판매 5·잔량 15 | 30 |
| B에서 미판매 5개 회수 후 | 배정 10·판매 10·잔량 0 | 현재 배정 15·판매 5·잔량 10 | 25 |

30개는 허용하며 30개 미만은 거절한다. 최초로 배정했던 수량을 영구 고정하는 것이 아니라, 합법적인 회수 후의 현재 배정 기준량으로 하한을 계산한다. 단 판매·취소·손실 이력을 지우기 위해 과거 배정량을 낮추지 않는다.

기존 자료의 알려진 창고 파손/분실/외부 차감과 행사별 판매 외 소비량도 보존한다. 따라서 일반화한 하한은 **행사별 현재 배정 기준량 합계 + 별도로 보존해야 하는 창고 차감량**이다. 행사 배정에 이미 포함된 차감은 다시 더하지 않는다. 기존 코드의 unavailable 계산을 단순한 판매+잔량 계산으로 교체해 손실이나 과거 차이를 지우지 않는다.

- 총개수 증가는 입고 또는 근거 있는 정정으로 기록한다. 실제로 10개를 추가 제작/입고했다면 입고 10개를 먼저 반영하고 A 행사에 추가 배정한다. A의 배정 증가는 총개수 증가와 별개의 두 번째 입고가 아니다.
- 총개수 감소는 미배정 가용량 안에서만 한다. A 10/B 10으로 전부 배정된 상태에서 5개를 줄이려면 해당 위치에서 정당하게 회수하거나 파손/분실을 기록해야 한다. 총개수 입력만으로 B의 수량을 자동 차감하지 않는다.
- 종료 행사에 3개가 남았다면 회수 전까지 그 3개는 행사 배정량이다. 판매된 수량은 남기고 미판매 잔여만 미배정으로 돌린다. 보관·마감 제한은 유지하며, 정리 작업은 허용된 회수/마감 해제 절차를 따른다. 자동 마감 해제·과거 판매 재작성은 하지 않는다.
- 판매 취소/환불 수량은 원래 행사 잔량으로 복원하고 하한을 다시 계산한다. 회수 후 취소에서도 미배정에 중복 복원하지 않는다.
- 동일한 하한·권한·재고 부족 검사를 화면과 서버 저장에 적용한다. 늦게 도착한 오프라인 주문도 서버에서 검사하며, 거절된 주문 큐를 삭제하거나 성공 처리하지 않는다.
- 하한 거절 시 필요한 오류에 최소 수량과 계산 근거를 표시한다. 반복 성공 알림이나 상시 사용법 안내를 새로 추가하지 않는다.

## 운영자 재고관리 허용

계정 설정에 **행사 운영자의 재고관리 허용**을 둔다. 신규 가입 시 체크된 기본값으로 제공하고, 같은 위치에 “내가 참여한 부스의 운영자가 내 재고 수량을 수정할 수 있습니다. 설정에서 언제든 변경할 수 있습니다.”를 표시한다. 가입자가 체크를 해제할 수도 있어야 한다.

- 첫 적용은 작가 계정의 전체 허용/미허용 하나로 한다. 같은 계정에 연결된 여러 원본 작가 프로필에도 그 설정을 일관되게 적용한다. 부스별 예외 UI는 이번 범위에서 보류하되 향후 작가–부스 관계로 확장할 수 있게 설계한다.
- 허용은 아무 행사 관리자가 아니라, 작가가 참여를 수락하거나 계정 연결로 확인한 부스의 실제 운영자에게만 적용한다. 운영자가 검색해서 행사에 등록했다는 사실만으로 이 수량 관리 위임을 새로 얻지는 않는다. 행사 판매 담당자/부관리자라는 이름만으로 총재고 관리 권한을 추정하지 않는다.
- 허용된 운영자는 해당 작가의 상품 수량 등록·총개수 수정·권한 범위의 행사 배정/회수·수량 차감을 관리할 수 있다. 원가·이미지·상품 원본 정보·계정·정산 수취인 변경까지 자동 허용하는 설정은 아니다.
- 미허용 전환 후 운영자의 새 수량 등록·총개수 수정·배정/회수·로스 정정 요청은 서버에서 즉시 거절하고 해당 화면을 읽기 전용으로 바꾼다. 작가 본인 관리는 유지한다. 이미 허용된 행사 판매·판매 취소와 그에 수반되는 재고 차감/복원은 그대로 유지한다. 미허용을 이유로 행사 판매를 중단하거나 미전송 주문을 지우지 않는다.
- 미연결 대리 프로필은 기존 대리 관리 범위를 유지한다. 계정 연결 후에는 연결 대상 계정의 설정을 적용한다. 신규 계정의 기본값은 허용이지만 기존 계정이 꺼 둔 설정을 연결 과정에서 다시 켜지 않는다. 초대/연결 확인에서 현재 설정을 확인하고 즉시 끌 수 있게 한다.
- 기존 계정의 최초 설정값은 기존 관리 상태를 보존하는 허용으로 이행하되, 설정 화면에서 상태와 변경 기능을 제공한다. 계정 연결/설정 변경은 과거 거래·재고 숫자를 재계산하지 않는다.

## 다른 행사와 부스의 경계

총재고 관리 위임은 다른 행사 배정까지 무조건 수정하는 권한이 아니다. A 운영자가 B 배정을 회수하려면 B 행사에도 실제 재고 관리 권한이 있어야 한다. 같은 부스의 여러 행사를 관리하는 운영자라면 각 행사의 상태 제한 안에서 조정할 수 있다. B가 다른 부스이고 그 권한이 없다면 B의 상세·배정·판매를 조회/변경하지 못하며 총 배정량 요약만 사용한다.

즉 예시의 추가 입고 10개를 A에 배정하는 것은 허용 범위에서 가능하지만, 부족한 5개를 B에서 임의로 빼는 것은 B 권한과 회수 가능한 잔량이 있어야 한다. 위임 해제·참여 종료·정산 마감 등 기존 제한을 총개수 수정으로 우회하지 않는다.

## 변경 이력

수량 변경마다 실제 작성자, 원본 작가/상품, 권한 근거 부스, 작업 행사, 변경 전후 총개수·배정량·증감, 입고/정정/회수/로스 사유, 요청 식별자와 서버 시각을 보존한다. 작가 본인은 자기 재고 변경 이력을 볼 수 있어야 하며, 다른 부스의 비공개 상세를 권한 없는 운영자에게 노출하지 않는다.

## 구현 구분과 후속 완료 기준

공유 원본 상품 등록/행사 배정·회수, 총재고 하한과 수량 변경 영수증에 더해 가입/계정 설정의 기본 허용 체크박스, 미허용의 서버 강제, 확인된 참여 관계에 따른 위임 적용을 로컬 구현했다. 기존 디자인을 재사용하며 행사 상세에서 총개수·배정/회수를 수정하고 기존 원본 상품을 검색해 가져올 수 있다. 검색 등록만 된 참여 관계는 마이페이지에서 작가가 참여 수락해야 운영자에게 수량 위임이 열린다. 판매·취소와 별도의 상품 정보/제작자 매핑 권한은 유지한다.

- [x] 03 계정·연결: 가입 기본값/고지, 개인 설정, 연결 대상 기존 설정 보존, 연결 확인의 해제 선택, 참여·위임 범위 구현.
- [x] 04 재고: 운영자 총개수 편집 UI, 모든 수량 쓰기의 위임 확인, 판매/취소 비영향, 종료 행사 회수와 손실 포함 하한 표시 대조.
- [x] 격리 DB/컴포넌트 회귀: 30 허용/29 거절, B 잔여 회수 후 25 하한, 추가 입고 한 번 계상, 타 행사 무권한 회수 거절, 미허용 즉시 쓰기 차단·판매/취소 유지, 기존 설정이 연결로 재활성화되지 않음, 원본/과거 판매/변경 이력 보존.

실제 브라우저·모바일·실계정 왕복과 PostgreSQL 다중 연결·배포 캐시 검증은 미실행이다. 기존 계정과 참여 관계의 최초 열 기본값은 허용/확인으로 기존 운영 상태를 보존하고, 새로 검색 등록하는 타 계정 관계는 확인 전 상태로 생성한다. 기존 계정의 미허용 값은 재초기화·연결 시 덮어쓰지 않는다.


## 행사·제작자 삭제 시 수량 보존 (2026-10-23 후속)

- 행사 삭제는 전환된 부스에서 삭제 표시로 운영 목록을 정리한다. 남은 재고만 미배정으로 회수하고 총재고·다른 행사 배정·판매/소비 하한·정산 원장은 보존한다. 회수는 기존 제작자 위임 조건을 적용하며 임의로 다른 행사 수량을 바꾸지 않는다.
- 행사 참여 제작자 삭제는 현재 상품의 제작자 연결만 해제한다. 원본 제작자의 재고/소유권/수량과 과거 귀속은 그대로 유지한다. 상품은 미연결로 표시하고 해당 행사 운영자는 기존 위임 범위에서 재고를 관리한다. 제작자 연결 해제로 재고를 새로 만들거나 원본을 삭제하지 않는다.
