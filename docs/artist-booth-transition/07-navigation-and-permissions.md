# 작가 중심 메뉴 재배치 가이드

2026-10-22. 사용자 제안과 확인된 메뉴 원칙을 반영한 다음 구현 가이드다. **이 문서의 메뉴 재배치·행사별 참여/대리 권한은 아직 구현하지 않았다.** 현재 01~04/06의 계약을 유지하고, 05 기업 모드는 제외한다.

## 이번에 반영한 메뉴 원칙과 진행 순서

아래 항목은 사용자 요청으로 가이드의 구현 기준에 반영한다. 세부 역할별 추가 권한은 뒤의 권한표와 같이 제안으로 구분한다.

- **부스 관리 진입점은 행사 선택 화면에 둔다.** 행사가 없어도 부스 정보와 공통 멤버를 관리한다. 행사에 참여하는 작가/대리 권한과 부스 공통 멤버 관리는 구분한다.
- **재고관리와 작가 재고를 재고관리 하나로 통합한다.** 기본은 내 작가 재고이며 운영자는 관리 부스의 참여 작가를 선택하여 대리 관리한다.
- **수익현황은 항상 내 기준으로 조회한다.** 부스 전체 매출과 작가별 지급 관리는 해당 행사의 정산현황에서 처리한다.
- **행사별 권한 → 개인 기준 재고·수익 → 행사 관리 → 메뉴 재배치** 순서로 구현하고 각 단계에서 검증한다. 참여 작가에게 기존 운영자 전체 조회를 열어 주지 않도록 서버의 본인/행사 범위를 먼저 나눈다.

## 데이터 전환과 화면 전환의 현재 상태

'기존 admin 부스에 구형 요청 종료를 적용했다'는 말은 **새 구조의 서비스 전환 전체를 완료했다는 뜻이 아니다.** 실제 적용한 범위를 아래처럼 구분한다.

| 구분 | 현재 상태 |
| --- | --- |
| 기존 자료의 새 관계 연결 | 실제 DB에 기본 부스, 행사 연결, 46개 재고의 소유자 연결, 미연동 작가 프로필 8개 등의 관계를 추가했다. 원본 재고·상품·거래와 기존 ID는 유지했다. |
| 작가 본인 계정 연결 | 초대/연결 기능은 로컬 구현했다. 기존 작가 후보를 실제 로그인 계정과 연결한 것은 아니며 이름만으로 본인임을 확정하지 않는다. |
| 작가 기준 공동 재고·직접 행사 배정 | 새 API/화면의 로컬 구현과 격리 검증은 완료했다. 기존 재고관리의 모든 등록·엑셀·이미지·차감 화면을 새 작가 기준으로 통합한 것은 아니다. |
| 구형 요청 종료 | 기존 admin 부스에 종료 정책을 실제 저장했다. 이 정책을 읽는 최신 서버 코드에서 부스/수취인 ID 등의 새 요청 조건을 검사한다. 앱 배포는 수행하지 않았다. |
| 전체 메뉴·개인 집계·행사별 대리 권한 | 이 문서에 따라 구현할 후속 작업이다. 현재 기존 운영 계정 집계를 개인 수익 집계로 해석하면 안 된다. |
| 기존 저장 테이블·열의 교체 | 완료하지 않았다. 기존 저장 형식을 사용하면서 새 관계를 추가한 호환 구조이며, 활성 참조를 교체하기 전에는 구형 열·별칭을 제거하지 않는다. |

판매 126건·2,966,000원과 재고가 같다는 것은 **전환 과정에서 원본이 손상되지 않았음을 대조한 결과**다. 모든 화면이 새 구조를 사용한다거나 실제 작가 계정 연결·새 앱 배포가 끝났음을 증명하는 수치는 아니다. 실제 관계 이관은 [02 기록](02-data-migration.md), 구형 요청 종료는 [06 기록](06-data-retirement.md)을 따른다.

## 기본 방향

상위 메뉴는 제안한 **대시보드 / 행사 선택 / 재고관리 / 수익현황 / 마이페이지** 5개를 사용한다. 로그인한 작가를 기본 문맥으로 삼고 행사를 고르지 않아도 재고와 내 수익을 이용할 수 있게 한다. 현재 별도 메뉴인 `작가 재고`와 `재고관리`는 작가 기준의 재고관리 하나로 통합한다.

데이터 관계는 `작가 → 보유 재고 → 부스에서 사용할 행사 재고 → 판매·정산`의 흐름이다. 부스 자체는 여러 행사에서 재사용하며 작가와 참여 관계를 가진다. 따라서 부스를 행사 안에서만 생성·삭제되는 대상으로 만들지 않는다. 같은 작가의 재고를 부스마다 복사하지 않는다.

```text
대시보드                          로그인한 나의 요약
행사 선택                         참여하거나 운영하는 행사
  ├─ 부스 필터 / 부스 만들기 / 부스 관리
  └─ [부스 · 행사 선택]
      ├─ 판매 목록(POS)           판매 권한이 있는 사람
      ├─ 행사 판매 설정           참여 작가: 본인 상품, 운영자: 행사 전체
      ├─ 정산현황                 참여 작가: 본인 정산, 운영자: 행사 전체
      └─ 행사 관리                운영자, 별도 권한을 받은 관리자
          ├─ 기본 정보·일정
          ├─ 참여 작가·초대
          ├─ 판매 담당자·대리 권한
          └─ 마감·보관·이력
재고관리                          기본값: 내 작가 프로필
  ├─ 재고목록
  ├─ 상품추가
  ├─ 엑셀 일괄등록
  └─ 외부판매·로스
수익현황                          내 작가 귀속분의 전체 행사 합계
마이페이지                        계정·프로필·연결·개인 설정
```

`행사 선택`은 항상 상위 메뉴에 표시한다. 행사 선택 후에만 하위 메뉴를 보인다. 선택한 `부스명 · 행사명`과 내 역할을 행사 영역에 표시하며, 다른 상위 메뉴로 이동해도 선택 자체는 유지한다. 로그인 후 기본 진입은 대시보드를 권장하고, 권한이 있는 행사 URL 직접 진입은 유지한다. 참여 작가의 행사 기본 진입은 정산현황, 판매 권한자의 기본 진입은 판매 목록으로 한다.

## 상위 메뉴의 범위

| 메뉴 | 기본 범위 | 운영자에게 추가로 필요한 범위 |
| --- | --- | --- |
| 대시보드 | 내 보유/미배정 재고, 참여 행사, 내 정산 대기 | 운영 부스·행사 바로가기; 운영 매출과 개인 귀속분은 구분 |
| 행사 선택 | 내가 참여한 행사, 내가 운영하는 행사 | 부스 필터, 부스 생성/관리, 행사 생성 |
| 재고관리 | 내 작가 프로필의 상품·총재고·위치별 배정 | 관리 부스의 참여 작가 선택 후 대리 관리; 진입 시 내 재고가 기본 |
| 수익현황 | 모든 부스/행사의 내 판매 귀속·비용·정산금·지급 내역 | 부스 전체 금전 관리는 해당 행사의 정산현황에서 수행 |
| 마이페이지 | 로그인 정보, 작가 표시 프로필, 기존 후보 연결, 계정 설정 | 부스 운영 권한은 계정 유형이 아니라 부스/행사 관계로 관리 |

계정이 여러 과거 프로필과 연결되어 있으면 영구 owner/recipient ID로 본인 귀속을 합산하되 원본을 병합하지 않는다. 동명이인도 이름으로 합치지 않는다. 외부판매·로스의 기존 기능은 재고 차감 기록이며 금액을 받지 않으므로 개인 수익에 추정 합산하지 않는다.

## 부스 관리와 행사 관리

상위 메뉴를 늘리지 않고 행사 선택 화면의 `부스 관리`에서 부스 이름, 공통 멤버, 부스 소유자/운영자, 초대·참여 상태를 관리한다. 행사가 하나도 없는 부스도 관리할 수 있어야 한다. 새 행사를 만들 때 소속 부스를 선택하고, 부스가 없으면 먼저 만든다.

행사 관리의 `참여 작가`는 부스 공통 멤버 중 **이번 행사에 참여하는 작가**를 관리한다. 부스에 속해 있다는 이유만으로 그 부스의 모든 행사에 참여하거나 정산 조회 권한을 얻지 않는다. 행사 참여 종료, 부스 탈퇴, 프로필 연결 해제는 구분하며 과거 귀속·정산 기록은 보존한다.

계정 없는 작가는 기존처럼 대리 프로필로 먼저 등록하고 해당 행사에 포함한다. 나중에 계정을 연결해도 재고·거래를 복제하거나 새 정산금을 만들지 않는다. **작가 소유 프로필 연결 초대와 판매/부관리자 권한 초대는 서로 다른 목적**이며 자동으로 권한을 함께 주지 않는다.

마이페이지의 부스 만들기/부스 멤버 초대와 구형 쓰기 계약 설정은 부스 관리로 옮기고, 기존 작가 후보와 본인 계정을 연결하는 기능은 마이페이지에 둔다. 백업은 실제 범위를 유지한다. 현재 보관 계정 전체 백업을 단순히 '내 작가 백업'이나 '이 행사 백업'으로 이름만 바꾸지 않는다. 개인 작가 전체 백업은 별도 데이터 추출/복원 계약이 필요하며 기존 부스 원본 백업은 운영자 데이터 관리에서 그 범위를 명시한다.

## 행사 역할과 권한 제안

기본 역할은 참여 작가 / 판매 담당 / 부관리자 / 운영자다. 한 사람은 참여 작가이면서 판매 담당이나 부관리자일 수 있다. 부스 소유자/운영자의 기존 권한은 유지하고, 새로 부여하는 대리 권한은 **선택한 행사에만 적용**한다.

| 기능 | 참여 작가 | 판매 담당 | 부관리자 | 운영자 |
| --- | --- | --- | --- | --- |
| 판매 목록·판매/취소 | 숨김/금지 | 허용 | 허용 | 허용 |
| 본인 행사 상품·배정·가격 조회 | 허용 | 작가 참여도 가진 경우 허용 | 행사 전체 허용 | 행사 전체 허용 |
| 행사 설정 수정 | 본인 것만, 행사 기간 밖에서 | 본인 작가 권한이 있으면 동일 | 행사 전체, 행사 기간에도 허용 | 행사 전체, 행사 기간에도 허용 |
| 정산현황 | 본인 귀속만 | 본인 작가 권한이 있으면 본인 귀속만 | 기본 본인 귀속만 | 행사 전체 |
| 행사 공통 비용·지급 변경 | 금지 | 금지 | 기본 금지 | 허용 |
| 참여 작가 초대/참여 종료 | 금지 | 금지 | 기본 금지 | 허용 |
| 판매/부관리자 권한 부여 | 금지 | 금지 | 금지 | 허용 |
| 행사 기본 정보·일정 | 조회 | 조회 | 기본 조회 | 수정 |
| 정산 마감/해제·보관 | 금지 | 금지 | 기본 금지 | 허용 |
| 부스 공통 멤버/소유권 관리 | 금지 | 금지 | 금지 | 부스 소유자 권한 범위 |

이 표의 부관리자는 **판매+행사 판매 설정 대리 권한**을 기본 묶음으로 제안한 것이다. 사용자가 지정하지 않은 정산·멤버·마감 권한까지 자동으로 확대하지 않는다. 필요 시 운영자가 추가로 부여할 기능을 분리한다. 부관리자라는 이유로 해당 작가의 타 부스 배정이나 모든 개인 창고를 수정하지는 못한다. 기존 부스 운영자의 참여 작가 총재고 공동 관리 정책은 유지한다.

메뉴 숨김·읽기 전용은 서버의 동일 범위 권한 검사와 함께 구현한다. 참여 작가용 응답에는 타 작가 정산, 전체 판매 내역, 비용 메모나 개인 정보 자체를 보내지 않는다. 판매 담당에게 POS에 필요한 행사 상품/판매 범위를 주는 것은 작가의 개인 열람 권한과 별도로 검사한다.

## 행사 판매 설정과 재고관리의 연결

재고관리의 상품추가는 작가 소유의 원본 상품/재고를 만든다. 행사 판매 설정에서는 `내 재고에서 가져오기`, 이번 행사 수량, 행사 판매가, 세트·판매 노출을 다룬다. 원본 재고를 복제하지 않고 동일 상품의 행사 위치에 배정한다. 운영자가 작가 상품 20개를 새로 만들어 즉시 배정하면 총재고 20·행사 20으로 한 번만 입고한다. 기존 50개에서 20개를 가져오면 총재고 50·미배정 30·행사 20이다.

행사 선택 상태에서 상품을 추가할 때에는 소유 작가를 명시한다. 참여 작가는 본인이 기본이고, 운영자는 해당 행사의 참여 작가 중 선택한다. 신규 상품을 어느 작가에게 귀속할지 행사/보관 계정에서 추정하지 않는다.

재고 상세에서는 본인의 부스·행사별 배정 위치를 확인하고 해당 행사 판매 설정으로 이동한다. 대리 운영 문맥에서는 다른 부스의 상세는 보이지 않는다. 총재고/입고 정정과 행사 배정 변경은 동작을 구분해 판매 당일 우회 수정을 막는다.

| 행사 기간 중 | 본인 상품 읽기 전용 | 운영 권한이 있는 사람만 행사 재고·가격 변경; 판매는 판매 권한 검사 | 본인 또는 전체 예상 |
| 일정 미설정 | 안전하게 읽기 전용 | 운영자만 일정/행사 재고 변경 | 기존 규칙 유지 |
| 정산 마감 | 읽기 전용 | 판매·취소·행사 재고 수정 금지 | 확정 숫자 조회, 운영자 지급 기록 |
| 보관 | 읽기 전용 | 권한자만 기존 규칙으로 보관 해제 | 기록 조회 |

기간은 한국 시간의 시작일~종료일을 양끝 포함한다. 행사 기간 종료와 정산 마감, 보관은 다른 상태다. 날짜가 지났다는 이유로 미동기화 주문을 버리거나 정산을 자동 마감하지 않는다. 미배정 개인 재고 입고/정정은 행사 수량을 변경하지 않는 범위에서 계속 가능하다.

행사 관리에는 기존 비용·정산 화면과 연결되는 `정산 마감/해제`를 배치한다. 공통 비용 입력과 작가별 금액은 정산현황에 두고 중복 편집 폼은 만들지 않는다. 마감 전 전체 기기 동기화와 금액을 확인하고, 마감 후 지급을 기록한다. 지급이 남아 있으면 기존 해제 제약을 유지한다. 보관/복제와 삭제 제한도 원본 보존 정책을 유지한다. 별도의 새 '영업 종료' 상태는 필요성이 정해지기 전 추가하지 않는다.

현재 `pos_booth_members`의 manager/seller를 행사별 대리에 그대로 재사용하면 다른 행사까지 열릴 수 있다. 행사별 관계를 추가하고 `actorId + boothId + projectId + capability`로 검사해야 한다. 공유 재고의 당일 검사도 기존 부스 운영자뿐 아니라 해당 행사에 설정 권한이 있는 대리인을 명시적으로 포함해야 한다. 원래 작가 권한을 행사 당일 무조건 열어 주는 방식으로 확장하지 않는다.

## 구현 순서와 검증 TODO

1. **행사 권한 기반**: 행사 참여 관계와 판매/설정 대리 권한·철회·감사를 추가한다. 부스 공통/행사별 권한을 분리하고 본인 조회 범위를 먼저 만든다. 운영자/대리의 권한 확대는 항상 명시적이다.
2. **개인 기준 데이터**: 소유자 ID 기반 재고 CRUD·엑셀/이미지/차감과 내 대시보드·수익 집계를 통합한다. 기존 46개 재고와 과거 판매 귀속을 대조하고 현재 공유 재고 API를 우회하는 구형 쓰기를 없앤다.
3. **행사 관리**: 참여 작가 초대/선택·미연동 후보·역할 편집·일정·마감 연결을 만든다. 행사에서 제외해도 정산/판매 원본은 보존한다.
4. **메뉴·라우팅**: 상위 5개로 정리하고 역할별 하위 메뉴·직접 URL 접근·초기 화면·부스/행사 선택을 연결한다. 기존 `/artist-stock` 링크는 통합 재고로 안내 없이 이동하며 미저장 편집·대기 주문을 보존한다.
5. **종합 검증**: 일반 작가의 POS 접근 차단/본인 정산만 노출, 대리인의 지정 행사만 변경, 당일 작가 읽기 전용/대리 변경, 정산 마감 후 모든 쓰기 차단, 권한 철회 후 오프라인 재전송 거절·큐 보존을 확인한다. 대시보드/개인 재고 이동이 장바구니·행사 선택·큐를 섞지 않는지 검증한다.

권한 철회는 서버가 다음 요청부터 검사한다. 이미 오프라인 기기에 내려간 자료를 원격 삭제할 수 있다고 약속하지 않는다. 권한 거절을 임의의 다른 계정/행사로 재전송하지 않고 원본을 보존해 운영자가 해결한다. 미저장 보호·새로고침·뒤로/앞으로·권한 없는 URL과 실기기 오프라인은 메뉴 변경의 회귀 범위다.

이 순서는 화면의 메뉴 이름만 먼저 옮겨 기존 부스 전체 데이터를 참여 작가에게 노출하는 일을 막기 위한 작업 단위다. 각 묶음의 권한/수량/이력 회귀를 통과한 뒤 다음 묶음으로 진행한다. **이번 요청에서는 가이드까지 작성하며 새 메뉴/권한 구현 완료로 표시하지 않는다.**
