# 04 — 작가 재고의 직접 행사 배정·회수

상태: 완료(로컬 구현·격리 검증). 사용자의 2026-10-22 추가 지침으로 초기 납품 승인·예약 설계를 대체했다. [구현 기록](04-implementation.md)과 [정책 기준서 P15](policy-baseline.md)를 따른다.

[진행 현황](README.md) · [공통 계약·검증](common-contracts-and-validation.md)

## 확정된 운영 방식

- 작가 본인과 참여 부스 owner/manager가 총재고를 함께 관리한다. 요청·수락·거절·취소·예약은 만들지 않는다.
- 운영자가 A작가 a작품 20개를 행사에 등록하면 작가 총재고 20·행사 배정 20·미배정 0이다. 상품을 두 번 입고하지 않는다.
- 기존 b작품 50개 중 20개를 행사에 설정하면 총재고는 50이며 미배정 30·행사 배정 20이다.
- 작가는 행사 기간에 해당 행사 배정·회수·가격·행사 차감을 변경하지 못하고 운영자만 관리한다. 한국 시간 기준 시작일~종료일 양끝을 포함한다. 일정이 없으면 운영자만 수정한다.

## 구현 TODO와 결과

- [x] 원본 재고를 작가 소유 ID로 연결하고 여러 부스/행사가 같은 재고를 참조한다. 기존 7월 자료는 복사·초기화하지 않는다.
- [x] 작가/활성 운영자의 상품 등록·입고/총재고 정정과 직접 부스 참여를 제공한다. 개인 프로필 생성·임시 작가 연결은 03을 사용한다.
- [x] 기존 재고의 행사 배정·추가 배정·미판매 회수·행사 간 이동을 같은 잠금/버전/원장/요청 영수증으로 처리한다.
- [x] 미배정/행사 잔량 부족과 판매·로스로 소비한 초기 배정의 회수를 막고, 이동을 신규 입고로 합산하지 않는다.
- [x] 파손·분실·외부 판매를 소유자·위치·수량·작성자와 기록한다. 매출/정산금·책임을 자동 생성/차감하지 않는다.
- [x] 판매/취소는 기존 POS와 원래 행사·구성·소유자·수취인 스냅샷을 유지한다. 반환 후 취소는 원래 행사에 복원하고 마감은 거절한다.
- [x] 참여 종료 시 잔량/정산 미완료는 ending으로 남겨 신규 배정·대리 총재고 변경·판매를 차단하고 회수·정산·본인 과거 열람을 보존한다. 정리 후 종료를 재확인한다.
- [x] 행사 일정 저장과 서버 날짜별 권한을 구현한다. 작가의 전역 미배정 입고/정정으로 행사 수량을 간접 변경하지 않는다.
- [x] 작가 재고 화면과 판매 화면/IndexedDB 갱신·동일 기기 대기 주문 차단을 연결한다. 다른 탭은 재고 변경 통지 뒤 인증된 API로 다시 조회한다.
- [x] 공유 자료의 기존 전체 교체 복원/삭제와 구형 재고 쓰기 우회를 차단하고 백업에 관계·원장을 포함한다.

새 납품 승인·가격 재승인·예약·부분 수락·부스 중간 보관 위치는 사용자 지침에 따라 구현 대상에서 제외한다. 작가 계정 연결의 본인 확인 초대는 03의 별도 보안 절차로 유지한다.

## 검증과 남은 범위

- [x] 새 상품 20개가 작가/행사에 중복 입고되지 않음, 기존 재고 100/A40/B20/판매5/반환/취소의 합계 보존을 검증한다.
- [x] 일정 미설정/행사 당일 작가 거절, 행사 밖 작가 허용, 당일 운영자 허용, 개인 미배정 입고가 행사 수량을 바꾸지 않음을 검증한다.
- [x] 타 부스 상세 비공개·임의 행사 접근 거절·회수 하한·중복 요청/내용 충돌·오류 주입 롤백·원장 실패 후 같은 요청 재시도·구형 API 우회 차단·참여 종료 후 늦은 판매 거절을 검증한다.
- [x] UI 모형에서 날짜 권한에 따른 행사 필드 비활성화와 응답 유실 후 동일 요청 재확인을 검증한다.
- [ ] 별도 실제 PostgreSQL 다중 연결 경쟁, 실제 다기기 오프라인/브라우저/모바일·배포 캐시 검증은 공개 운영 전 수행한다. PGlite 순차 테스트로 대체하지 않는다.
