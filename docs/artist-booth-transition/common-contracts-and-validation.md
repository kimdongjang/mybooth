# 공통 계약·전환·검증 기준

상태: 계획. 각 단계는 자기 범위에 해당하는 항목을 실행하고 결과를 해당 단계 문서에 기록한다. 이 문서의 항목을 한 번에 모두 구현하는 작업으로 사용하지 않는다.

[진행 현황](README.md)으로 돌아가기.

담당 단계: 권한·삭제·구형 큐·백업·정산 식별자·전환 복구는 02에서 기반을 마련하고, 초대·작가 열람은 03, 납품·반환·재고 경쟁은 04, 기업 화면은 05, 구형 계약 제거는 06에서 완료한다. 후속 단계는 기존 기반의 회귀를 확인한다. 01은 정책과 검증 계획만 확정한다.

정책 근거: [01 정책 기준서](policy-baseline.md). 작가가 부스를 만들고 운영하며, 참여 작가와 부스 owner/manager 모두 작가 총재고를 관리한다(P01/P02). 총재고 공동 관리와 타 부스 배정 변경 권한은 구분한다(P04).

## 모든 단계의 필수 작업 — 오프라인·정산·데이터 수명

### 오프라인과 구버전 호환

- [ ] `src/database/dexie.ts`, `orderRepository.ts`, `stateRepository.ts`의 큐·상태 키를 검토하고 사용자/부스/행사 격리를 설계한다.
- [ ] 구형 주문의 projectId / localOrderId / payload를 보존한다. 확정 가능한 매핑만 적용하고 불명확한 주문은 진단·복구 대상으로 남긴다.
- [ ] `src/sync/syncService.ts`, `src/hooks/useSync.ts`, `src/App.jsx`에서 문맥 변경 중 늦은 응답·재시도·다른 탭 동기화가 현재 화면/큐를 오염시키지 않게 한다.
- [ ] 서버는 동기화 시점의 권한·행사 revision·마감 여부를 다시 검사한다. 거절된 큐를 자동 성공 처리하거나 삭제하지 않는다.
- [ ] 연결·권한·납품 승인·복원은 온라인 작업으로 먼저 제한하고 오프라인 범위는 행사 판매/취소 중심으로 유지한다.
- [ ] `public/sw.js` 및 Android 구형 클라이언트와의 API 버전 호환/최소 버전 정책을 정한다. 캐시 갱신만으로 미전송 큐가 없어지지 않게 한다.

### 정산과 보존

- [ ] `api/settlements.js`, `api/lib/eventSettlement.js`, `src/utils/revenueSummary.js`, `src/utils/dashboardSummary.js`, 정산/수익 화면을 수취인 ID 기준으로 바꾼다.
- [ ] 마감 이후 판매/취소·배정 변경 차단, 지급 후 마감 해제 제한, 부분 지급/지급 취소·음수 정산·원 단위 합계 보존을 유지한다.
- [ ] 판매 금액·작가 귀속 매출·정산 예정·지급 기록을 구분한다. 결제/지급 버튼은 실제 입금 확인·송금·PG 승인을 수행하지 않는다.
- [ ] 부스 삭제는 우선 보관/종료로 처리하고 작가 거래·미지급금·마감 스냅샷에 대한 CASCADE 삭제를 제거/제한한다.
- [ ] 계정 탈퇴는 구성원 권한과 개인정보를 처리하고 공동 부스·다른 작가 자산을 지우지 않는다. 유일 소유자는 승계 또는 종료 조건을 적용한다.
- [ ] 기존 계정 전체 백업/복원을 새 공유 모델에 그대로 적용하지 않는다. 개인 소유 자료와 부스 자료의 백업 단위·복원 권한·버전·서명을 정의한다.
- [ ] 구형 백업은 별도 변환 경로로 지원하고 기존 공유 부스 덮어쓰기를 차단한다. 이미지 참조와 실제 파일 보존 범위도 명시한다.
- [ ] `upsertDefaults`/`resetDefaults`의 대상 소유자·부스를 명확히 하고 미동기화 차단 및 판매 보존 정책을 유지한다.
