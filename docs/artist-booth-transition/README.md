## 2026-10-23 재고 관리 정책 후속

[행사 운영자의 작가 재고 관리 정책](inventory-management-policy.md)을 채택했다. 운영자 총개수 관리, 배정/소비분을 보존하는 하한, 가입 기본 허용·작가의 해제, 확인된 참여 부스 범위와 변경 이력이 기준이다. 원문 3번 동시 수정 제안은 추가 범위에서 제외한다. 03/04의 기존 완료 표시는 과거 구현이며, 후속 작업에서 가입·마이페이지 설정, 참여 확인과 위임 서버 검증, 행사 상세 총개수/배정 편집과 기존 상품 가져오기를 로컬 구현했다. 실제 DB 적용·배포·실기기 확인과 격리 회귀는 구분한다.

현재 확인점: **[06 실제 적용·보존 결과](06-data-retirement.md)**. 사용자 기기 확인 후 기존 admin 부스의 종료 정책을 적용했다. 다른 계정은 그대로다. 과거 거래/백업/재고 저장이 참조하는 열·별칭은 유지한다. 05는 제외하며 실제 작가 계정 연결·앱 배포·물리 열 제거는 수행하지 않았다. [04 지침](04-implementation.md)과 [01 정책](policy-baseline.md)을 유지한다. P16 보존/파기는 후속이다.

다음 메뉴/권한 변경의 가이드는 [작가 중심 메뉴 재배치](07-navigation-and-permissions.md)에 작성했다. 사용자 요청으로 행사 선택의 부스 관리 진입점, 내 재고 기본/참여 작가 대리 관리, 내 기준 수익현황, 행사별 권한 → 개인 기준 재고·수익 → 행사 관리 → 메뉴 재배치 순서를 구현 기준으로 반영했다. 세부 대리 권한은 제안이며 메뉴/권한 구현은 아직 완료하지 않았다. 기존 자료의 관계 연결·원본 보존과 서비스 전체 전환 완료는 구분한다.

## 작업 방법

1. 현재 단계의 시작 조건과 최신 코드·git diff를 확인한다.
2. 이번에 수행할 체크박스 묶음과 완료 기준을 정한다. 큰 단계는 여러 작업으로 나누되 앞 단계의 계약을 유지한다.
3. 같은 단계 안에서 필요한 서버·클라이언트·큐·정산·복구를 함께 처리한다.
4. 해당 검증을 수행하고 단계 문서의 작업 결과 기록을 갱신한다.
5. 필수 조건이 충족되면 이 표의 상태를 완료로 바꾸고 다음 단계의 시작 조건을 확인한다. 미실행 검증과 결정되지 않은 정책을 숨기지 않는다.

상태는 미착수 / 진행 중 / 검증 중 / 완료로 관리한다. 실제로 필요한 입력이 없으면 진행 중에 해당 의존을 기록한다. 전체 로드맵의 체크박스와 중복 관리하지 않고 상세 진행률은 단계 문서에만 기록한다.

## 작업 요청 예시

> docs/artist-booth-transition/01-policy.md의 범위만 진행해줘. 현재 코드를 근거로 권한표·재고 상태표·삭제/보존 정책·이관 대응표를 구체화하고, 미확정 결정은 제안과 구분해 기록해줘. 기능 구현은 시작하지 마.

> 01의 확정 정책과 docs/artist-booth-transition/02-compatibility.md를 읽고, 먼저 스키마 확장과 기본 부스/ID 매핑 묶음을 진행해줘. 기존 데이터를 보존하고 관련 검증 결과·남은 항목·다음 시작점을 기록해줘. 03의 작가 연결과 04의 납품 기능은 포함하지 마.

단계 문서는 계획과 결과를 함께 보관한다. 구현으로 계약이 바뀌면 하네스 문서도 갱신한다. 로컬 작업 정책에 따라 별도 요청 없이 커밋·푸시·PR·운영 배포를 하지 않는다.
