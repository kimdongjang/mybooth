# 02 기존 행사 자료 이관 결과

실행일: 2026-10-22. 사용자 확인: 서비스는 아직 운영 전이며 실시간 판매/데이터 변경은 없다. 기존 행사·재고·판매 기록을 보존하면서 현재 설정 DB에 새 부스·작가 관계를 연결했다. 이관은 사용자 요청으로 실행했으며 앱 배포와 구분한다.

[진행 현황](README.md) · [02 구현](02-implementation.md) · [02 검증 기록](02-compatibility.md)

## 적용 범위와 보존 결과

기존 `admin` 계정에 기본 부스를 생성했다. 재고가 계정 단위로 연결되어 있어 7월과 같은 계정의 12월 행사를 함께 연결하되 행사 ID와 판매·재고를 합치지 않았다. 다른 계정의 10월·11월 행사에는 관계를 추가하거나 원본을 변경하지 않았다.

| 항목 | 이관 전 | 이관 후 |
| --- | --- | --- |
| 7월 서코행사 상품 | 41개 | 41개 |
| 7월 판매 | 122건 / 2,913,000원 | 동일 |
| 같은 계정 12월 행사 | 상품 5개 / 판매 4건 / 53,000원 | 동일 |
| 계정 전체 행사/상품·공통 재고 | 행사 2개 / 상품 46개 / 공통 재고 46개 | 동일 |
| 계정 판매 합계 | 126건 / 2,966,000원 | 동일 |
| 창고 잔량 / 행사 잔량 / 기존 초기 배정 합계 | 10 / 1,212 / 1,557 | 동일 |
| 세트 / 입고·정정 원장 / 이동 원장 | 7개 / 4개 / 2개 | 동일 |
| 정산·마감·지급 기록 | 현재 해당 계정에 없음 | 새 금액/지급을 만들지 않음 |
| 다른 계정 자료 및 공통 pos_meta | 원본 DB 지문 | 동일 |

새 관계는 행사 연결 2개, 상품 소유자 연결 46개, 초기 재고 원본 46개, 상품 귀속 연결 46개, 미연동 작가 프로필 8개다. 8개는 기존 작가명 7개와 미지정 묶음 1개이며 실제 로그인 계정과 연결하지 않았다. 이름은 프로필 후보 분류에만 사용했고 계정 소유권을 추정하지 않았다.

작가명이 없는 상품 4개(7월 2개, 12월 2개)는 원래 이름·재고·판매 이력을 그대로 보존했다. 실제 소유자는 이후 확인할 수 있으며 이번 이관 완료와 별개다. 알 수 없는 작가를 임의 배정하거나 상품을 삭제하지 않았다.

## 수행한 검증

1. 기존 DB를 읽기 전용으로 조사하고 대상 계정의 원본/스키마와 다른 계정 자료의 대조 지문을 백업했다. 인증 비밀번호/해시·이메일·토큰·연결 주소는 백업하지 않았다.
2. 백업으로 독립 PGlite DB를 만들고 실제 행사를 그대로 재현했다. 원본 지문을 비교한 뒤 이관 및 동일 이관 재실행을 통과했다.
3. 실제 PostgreSQL에서 하나의 트랜잭션으로 추가 스키마/관계를 생성했다. 최신 대상 원본과 백업 지문이 같아야 적용하며, 이관 후 대상 원본·다른 계정·공통 메타 지문을 다시 대조한 뒤 커밋했다.
4. 커밋 후 별도 읽기 전용 연결로 원본 지문과 모든 연결 건수를 재검증했다. sourceUnchanged, otherAccountsUnchanged, verified가 모두 true다.
5. 별도 fixture 회귀에서 백업 실패, 대상 변경, 다른 계정 변경, 미검증 계획 적용 거절과 전체 rollback을 확인했다.

## 백업과 재현 도구

원본과 실제 실행 보고서는 Git 제외 경로 `.local-archive/artist-booth-migration-2026-10-22/`에 보관한다.

- `admin-before.json`: 이관 전 원본/스키마·지문. 원본 복구용으로 보존한다.
- `admin-rehearsal.json`: 실제 자료 복사 DB 이관·재실행 검증 결과.
- `admin-applied.json`: 실제 DB 커밋 결과.
- `admin-verified.json`: 커밋 이후 읽기 전용 대조 결과.

`scripts/migrateLegacyBooth.mjs`는 inspect/export/rehearse/apply/verify 모드를 제공한다. export는 새 파일만 만들고, apply는 명시적 계정·백업·통과한 rehearsal을 요구한다. 적용 전후 원본과 다른 계정이 달라지면 rollback한다. 연결 설정은 서버 환경 파일에서 읽고 값이나 오류 스택을 출력하지 않는다. 이 도구는 DB 관리 작업용이며 공개 API의 인증 절차를 대체하는 사용자 기능이 아니다.

## 02 완료 판정과 다음 단계

기존 자료 이관과 보존 대조를 통과하여 02를 완료 처리한다. 사용자가 별도 SQL·DB 검증을 실행할 필요는 없다. 다음은 03의 작가 계정·초대·기존 프로필 연결이다. 미지정 4개는 연결 대상 확정 시 확인하면 된다.

현재 실시간 운영이 없으므로 다중 사용자 부하/교착·다기기 오프라인·Android/배포 캐시 검증은 공개 운영 전 별도 검증으로 남긴다. 이번 실제 PostgreSQL의 스키마·자료 이관 성공을 동시 운영 검증 통과로 확대 해석하지 않는다. 앱 코드는 로컬에 있으며 배포·커밋·푸시·PR은 수행하지 않았다.

## 최종 도구 검증

- `node --test tests/booth-migration-script.test.js`: 3개 통과. 실제 적용/커밋 후 검증, 백업 실패, 대상/다른 계정 변경 시 rollback을 확인한다. 테스트에는 실제 계정 자료나 연결 설정을 사용하지 않는다.
- `npm run build`: 통과. 기존 500kB 초과 청크 경고 유지. 기반 API·UI 기능 코드는 이번 후속 작업에서 바꾸지 않았다.
- 이전 전체 회귀 134개 통과 결과와 이번 새 이관 도구의 3개 결과를 구분한다. 이번 후속에서는 전체 회귀를 반복하지 않았다.
- 문서 링크·공백 검사와 `git diff --check`를 확인했다. 원본/실행 보고서 4개는 `.local-archive/`에 있어 Git에서 제외된다.
